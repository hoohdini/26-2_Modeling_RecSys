## 1. 주제 확정

### 디코딩을 접은 이유

이미 여러 팀이 하고 있었습니다. **TIGER 원논문 4장에 계층별 샘플링이 이미 있었고**, BARGE/HPR(2026.07), GRC(2026), MindRec 등 후속도 있습니다. 확인 없이 "아무도 안 했다"고 말씀드린 점 죄송합니다.

### 새 주제 — 층 수 × 구간

**세 논문이 서로 다르게 말합니다.**

| 논문 | 주장 | 구간별로 봤나 |
|---|---|---|
| TIGER (2023) | "길이 바꿔도 robust" | ❌ 수치 미제시 |
| GRID (2025) | "층 늘리면 하락" (3층 0.0422 → 5층 0.0396) | ❌ **전체 평균만** |
| VarLenRec (2026) | "인기는 짧게, 비인기는 길게" | ✅ |
| SA²CRQ (2026) | "인기는 길게, 비인기는 짧게" | ✅ **정반대** |

> **연구 질문**
> GRID가 본 "층 늘리면 나빠진다"는 **전체 평균**입니다.
> 구간별로 나누면 **인기는 나빠지고 비인기는 좋아지는 걸 평균 낸 결과** 아닐까요?

```
겹치는 구간이 L=4 하나뿐입니다

GRID       ●─●─●─●
           2 3 4 5
VarLenRec        ●───●───●───●
                 4   6   8  10

빈 곳: L=2,3 을 구간별로 본 사람이 없습니다
       그리고 GRID에 따르면 거기가 최적 구간입니다
```

**좋은 점**
- `num_hierarchies` 값만 바꾸면 됨 (코드 수정 불필요)
- **실패 시나리오가 없음** — 결과가 어느 쪽이든 의미 있음
- Ghost가 실제로 인기 5토큰 / 비인기 7토큰을 쓰고 Tail **+63.91%** 를 냈음 → 실증 근거

## 2. 🚨 조사하며 확인한 것

### ① TIGER는 공식 코드가 없습니다 — 구현마다 14% 차이

| 구현 | Beauty NDCG@10 | 원논문 대비 |
|---|---|---|
| **원논문** (3시드 평균) | 0.0374 | — |
| **GRID** (Snap) | 0.0347 | −7.2% |
| XiaoLongtaoo | 0.0321 | −14.2% |
| EdoardoBotta (835⭐) | **수치 미보고** | — |

> **"어느 구현을 썼느냐"가 "무슨 방법을 썼느냐"보다 영향이 큽니다.**
> 팀이 통일하지 않으면 마지막에 비교가 불가능합니다.

**제안: GRID로 통일.** 재현도 1위이고 5시드 평균 수치가 공개돼 있어 검증이 즉시 됩니다.
⚠️ 우리 개선폭은 **GRID 기준(0.0347)** 으로 보고해야 합니다. 원논문(0.0374)과 비교하면 안 됩니다.

### ② TIGER는 Recall이 아니라 NDCG를 올린 모델

```
Beauty  Recall@10   +0.15%    ← 맞히는 개수는 그대로
        NDCG@10    +17.43%    ← 맞힌 걸 앞으로 옮김
```

> **"더 많이 맞히는" 게 아니라 "순위를 잘 매기는"** 모델입니다.
> 우리 목표(안 뜨던 걸 뜨게 하기)는 **Recall 문제**입니다.

### ③ TIGER의 콜드스타트 강점은 만들어진 것

논문 원문 확인 결과, `ε`라는 값으로 **후보 목록에 신규 아이템 자리를 강제 예약**하는 방식입니다. 모델이 스스로 찾는 게 아닙니다.

2026년 7월 논문이 시간 기준으로 재실험하니 —
```
TIGER 신규 아이템 Recall@20
Beauty 0.00000 · Sports 0.00004 · Toys 0.00000
```

**"TIGER는 콜드스타트에 강하다"를 전제로 삼으면 안 됩니다.**

### ④ DGU/MGU는 롱테일 도달을 안 잽니다 (CRAB 지표)

```
DGU/MGU = "추천 분포가 과거 분포와 얼마나 다른가"
그런데 과거 분포 자체가 옛 시스템의 결과물
→ DGU=0 은 "옛 편향을 충실히 재현"한다는 뜻
```

Ghost가 노출 비율(43:1 → 1.6:1)을 **따로** 잰 이유입니다. CRAB은 이걸 안 쟀습니다.
**→ 롱테일 도달을 직접 재는 지표가 따로 필요합니다.**

### ⑤ 정확도와 exploration은 같이 올릴 수 있습니다

| 논문 | 정확도 | 다양성/공정성 |

**단, 조건이 있습니다**

**목표 문장** — *"정확도를 희생해 탐색을 늘리자"* ❌ → *"인기 편향이라는 **왜곡을 제거**하면 둘 다 개선된다"* ✅

## 3. 논문 정리

### 계보

```
TIGER (NeurIPS 2023, Google DeepMind)
   의미 번호(Semantic ID)를 생성해서 추천. 이 분야의 원점
        ↓
   ├─ LETTER (CIKM'24)      번호에 협업 신호 주입
   ├─ LC-Rec (ICDE'24)      LLM에 협업 의미 통합
   │      ↓  Ghost (2026.05)  SKT + AUO 추가 · Qwen2.5-3B
   ├─ CRAB (2026.04, Walmart)  코드북 리밸런싱
   ├─ VarLenRec / SA²CRQ (2026) 가변 길이 ID (서로 반대)
   └─ GRID (2025, Snap)      ⭐ TIGER 구현 + 어블레이션
```

### Ghost — 편향 원인을 규명

**진단**
```
① 그래디언트 기아
   비인기 토큰은 "오답 후보"로만 등장 → 계속 밀려남

② 분기점에서의 기하급수적 억제
   갈림길 z개면 살아남을 확률이 γ^z 로 감소

측정: 인기/비인기 성능 격차 최대 45배
```

**처방**
```
SKT   비인기가 가장 가까운 인기 아이템의 앞부분을 물려받음
AUO   "내용은 비슷한데 번호는 다른" 것을 억제
```

**결과 (LC-Rec 대비)**

| Tail HR@10 | Tail NDCG@10 | 불공정성 | 전체 HR@10 | 노출 비율 |
|---|---|---|---|---|
| 🟢 **+63.91%** | 🟢 +70.66% | 🟢 −55.76% | 🔴 −7.46% | **43:1 → 1.6:1** |

### CRAB vs Ghost

| | **CRAB** (Walmart) | **Ghost** |
|---|---|---|
| 목표 | 정확도 지키며 편향 줄이기 | 정확도 조금 내주고 롱테일 크게 |
| 정확도 | **손실 없음** | −7.46% |
| 롱테일 수치 | ❌ **없음** (공정성 지표만) | ✅ 43:1 → 1.6:1 |
| 콜드스타트 | ❌ 없음 | ❌ 없음 |
| 한계 서술 | ❌ **논문에 없음** | 있음 |
| **코드** | ❌ **없음** | ✅ **공개** (데이터 포함) |

⚠️ **CRAB은 코드가 없어 재현하려면 직접 구현해야 합니다.**

### 🚨 VarLenRec vs SA²CRQ 모순

```
VarLenRec:  인기 = 짧게 / 비인기 = 길게
            근거: 비인기는 협업 신호 부족 → 콘텐츠로 채워야

SA²CRQ:     인기 = 길게 / 비인기 = 짧게
            근거: 비인기에 고유 ID를 주면 고립 → 일반화 저해
            JD.com 실서비스. Tail 커버리지 +79%, 환각률 −28%
```

**모순의 정체 = 고유성 vs 공유**
```
긴 ID  →  정확하지만 고립
짧은 ID →  일반화되지만 구별 안 됨
```
**Ghost가 제3의 답** — 앞은 공유, 뒤는 고유

### Spotify GLIDE — 우리 목표를 실서비스에서 달성 (전원 필독 권장)

```
[오프라인]  Recall@30 +29.9%  ·  낯선 콘텐츠 NDCG@30 +35.4%
[온라인 A/B — 21일, 2천만 노출]
   비습관적 스트림 +5.4%  ·  신규 쇼 스트림 +14.3%  ·  회귀 없음
```

**핵심 기법 — 친숙/낯선 제어 토큰**
> 학습 때 제어 토큰을 넣고, **추론 시 토큰만 바꾸면 재학습 없이** 방향 전환.
> 낯선 모드 Recall@30 +11.8%

**인기 편향 완화 3종**
```
① Cross-surface sampling   피드백 루프 감소
② Exploration upweighting  무작위 배치에 높은 가중치
③ Popularity capping       아이템당 학습 예시 수 상한  ← 단순하고 강력
```

**교훈**
- **R-KMeans > RQ-VAE (+9.52%)** — RQ-VAE는 코드북 붕괴 때문에 프로덕션에서 취약
- 🚨 **오프라인 지표가 인기 편향에 속습니다** — recall이 높은 변형이 인간 평가에서 졌습니다

### 그 외

| 논문 | 핵심 |
|---|---|
| **SPRINT** (2026.06) | 모델을 키우면 인기 편향 증폭. 상위 20%가 어텐션의 75% 독식. **"디코딩은 다루지 않는다"** 명시 |
| **MMQ** (Alibaba) | 같은 토크나이저 개선인데 판별식 +0.04% vs **생성식 +32.73%** → 생성형을 고른 게 옳다는 근거 |
| **LETTER** | 논문이 인정한 한계: L=4가 최적(더 길면 오류 누적), 코드 쏠림 절반만 해결(76→148/256) |
| **ColdGenrec** (SIGIR'26) | 식별자 설계가 결정적. **조합적 코딩(OPQ)이 양쪽 다 좋음.** 🚨 RL은 콜드스타트를 해칠 수 있음 |

## 4. 직접 검증한 것

### Ghost 논문 핵심 주장 — 데이터 전수 조사

**SID 구조**
```
인기:   <a_143> <b_213> <c_203> <d_242> <p_1>                  5토큰
비인기: <a_30> <b_170> <c_159> <d_30> <e_143> <f_232> <p_1>    7토큰
        └──── 인기와 같은 4단계 ────┘ └추가 2단계┘
```

**접두사 상속 검증**

| 데이터셋 | 비인기 아이템 | 일치율 |
|---|---|---|
| Instruments | 8,075개 | **100.0%** |
| Arts | 16,921개 | **100.0%** |
| Games | 13,617개 | **100.0%** |

**38,613개 전부 일치. 불일치 0개.**

**부수적 확인 2가지**
```
① 구간 정의 호환성
   Ghost 실제 인기 비율 18.6~19.3%  ≈  VarLenRec 기준 20%
   → 비교 가능합니다

② Ghost는 VarLenRec 편입니다
   Ghost: 인기 5토큰(짧게) / 비인기 7토큰(길게)
```

### 🎯 논문에 없는 구조를 코드에서 발견

```
비인기 T의 앞 4토큰 = 반드시 어떤 인기 아이템 H의 접두사 (SKT 구조상)
      ↓
H를 억제 후보로 평가하면 일치 길이가 최댓값 → 정렬에서 맨 뒤로
      ↓
★ "자기 부모"는 억제 대상에서 자동 제외됩니다
```

**SKT가 AUO의 안전장치 역할을 합니다.** 코드를 읽어야만 보이는 구조입니다.

### GRID 데이터 실측

```
training  22,400개 ≈ 유저 22,363명   ← 유저당 정확히 1행
items     12,288개 ≈ 아이템 12,101개
```

**슬라이딩 윈도우 증강이 데이터에 없습니다.** GRID 논문은 "42% 차이"라고 했는데 데이터에도 전처리 코드에도 없었습니다.

**답은 `label_function` 설정입니다**
```
Identity            시퀀스 전체에서 a→b, b→c, c→d 를 한 번에 학습 (= 증강 효과)
NextKTokenMasking   마지막 K개만 (= 증강 없음)
```
**재현할 때 이 설정을 반드시 확인해야 합니다.**

## 6. 실험 계획

### ① 구간별 평가 인프라 (팀 공통)

**왜 필요한가** — Ghost 사례가 보여줍니다.
```
비인기 노출이 17배 늘었는데 전체 정확도는 7% 떨어졌습니다
→ 전체 평균만 보면 "성능이 나빠졌다"로만 보입니다
```

**구간**
```
HEAD 인기 상위 20% · BODY 중간 60% · TAIL 하위 20% · COLD 신규
```

⚠️ **TAIL과 COLD는 다릅니다.** 팀이 "비인기·신규"를 섞어 쓰고 있는데 구분이 필요합니다.

| | TAIL | COLD |
|---|---|---|
| 정의 | 학습에 **있지만** 적음 | 학습에 **없음** |
| TIGER 성능 | 나쁨 | **거의 0** |
| RL 효과 | 🟢 도움 | 🔴 해로울 수 있음 |

**출력 형식**
```
구간      n      HR@10   NDCG@10  노출수   Coverage
HEAD    2,420   0.2841   0.1922  18,340    94.2%
BODY    7,261   0.0912   0.0588   5,120    31.7%
TAIL    2,420   0.0104   0.0061     340     8.1%
COLD      187   0.0000   0.0000       2     0.5%
ALL    12,288   0.1122   0.0831  23,802    41.3%
```

### ② 층 수 × 구간 실험

```
Phase 0  재현 검증 — Beauty × L=3
           목표: Recall@10 0.0639, NDCG@10 0.0347 (±5%)
Phase 1  Beauty × L ∈ {2,3,4,5} × 시드 3 = 12회
Phase 2  + L ∈ {6,8}  (VarLenRec 범위와 겹치게)
Phase 3  + Sports, Toys
```

🚨 **충돌률을 반드시 같이 재야 합니다.** 안 그러면 "L이 작아서 나쁜지, 충돌이 많아서 나쁜지" 구별할 수 없습니다.

**핵심 결과물**
```
 HEAD  ●───●───●───●   ← 하락?
 TAIL  △───△───△───△   ← 상승?
       L=2  3   4   5

반대 방향이면 가설 지지
```
