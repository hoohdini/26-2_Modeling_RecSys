### 맥에서 TIGER 학습은 불가능합니다

```

Step 5 TIGER 학습    스텝당 27초  ❌ 320,000스텝 = 약 100일
```

⚠️ dataloader 워커를 올리면 **오히려 느려집니다** (0개 27초 / 6개 34초 / 12개 36초).
맥에서는 래퍼 기본값 0을 그대로 두세요.

⚠️ 속도를 잴 때는 `trainer.val_check_interval` 을 크게 잡으세요.
검증 시간이 섞이면 스텝당 2.3분처럼 5배 부풀려진 값이 나옵니다.

**→ Step 3·4·6 은 맥에서 개발·디버깅하고, Step 5만 랩 GPU에서 돌리면 됩니다.**
그래서 랩 GPU 사양 확인이 다른 무엇보다 급해졌습니다.

### GRID 기본 설정은 "증강 꺼진" 쪽입니다

```yaml
# configs/experiment/tiger_train_flat.yaml (배포된 기본값)
transform:
  _target_: src.data.loading.components.label_function.NextKTokenMasking
```

선택지는 `Identity`(증강 효과 있음) / `NextKTokenMasking`(없음) 둘인데
**기본값이 증강 없는 쪽**입니다. GRID 논문은 이 차이를 42%로 보고합니다.

⚠️ 단, "기본값으로는 논문 수치가 안 나온다"고 아직 단정하면 안 됩니다.
양쪽을 실제로 돌려 봐야 합니다. **재현 검증의 1번 확인 항목입니다.**

### ✅ 코드북 붕괴 — 원인 규명·수정 완료 (자세한 건 docs/10)

```
[증상]  같은 명령·같은 설정·같은 seed 42 인데 결과가 크게 달라졌습니다.
        L=4 를 두 번 → 충돌률 3.7% vs 63.3% (17배)
        층이 통째로 무너짐. 한 코드워드가 아이템의 95%를 삼킴.
        🚨 "코드워드 256개를 다 썼다"로는 못 잡습니다. 엔트로피로 봐야 합니다.

[원인]  GRID 가 tf.data 셔플에 시드를 안 넘깁니다 (버그 ⑥-2).
        L.seed_everything(42) 는 파이썬·NumPy·PyTorch 만 잡고
        TensorFlow 는 안 잡는데, 데이터 로딩이 TensorFlow 입니다.
        → 매 실행 다른 순서 → 신호가 얼마 안 남은 깊은 층이 가끔 넘어감

[수정]  patches/grid_local_fixes.patch 에 포함. 적용 후 검증:
        같은 명령 2회 → SID 텐서 비트 단위 완전 동일 (12,101×7, 차이 0개)

⚠️ 셔플을 끄는 건 해결책이 아닙니다. 아이템 id 가 인기도와 얽혀 있어서
   (순위상관 −0.42) 끄면 앞 배치에 인기 아이템만 몰립니다.
```

**패치 후 18회 재실험 결과 (L 6개 × 시드 42·43·44, max_steps=300)**
```
L        2       3       4       5       6       8
충돌   62.4%   13.7%    5.5%    1.5%    0.9%    0.4%
범위    ±0.7    ±0.5    ±1.8    ±0.2    ±0.1    ±0.2      ← 시드 간 폭이 좁음
붕괴    0/3     0/3     1/3     0/3     0/3     1/3

→ 충돌은 HEAD/BODY/TAIL 을 실질적으로 안 가립니다
  (TAIL−HEAD 평균 +0.23%p. 평균 충돌률 14% 대비 1.6% 로 무시할 크기)
→ 🌍 Sports·Toys 에서도 같습니다 (합계 34회). 데이터셋 간 차이는 아이템 수로 설명됩니다
  Beauty 62.4% / Sports 71.4% / Toys 62.0% (L=2). Sports 는 아이템이 1.5배라 여유 비트가 적음
  여유 비트(유효 − log₂아이템수) vs 충돌률 상관 −0.981 — 새 데이터셋의 L 을 미리 가늠 가능
→ 붕괴는 21% → 11% 로 줄고, 남은 것도 경미합니다 (63% 같은 폭발 없음)
→ 깊은 층은 원래 정보가 얼마 없습니다 (층별 7.1 → 6.0 → 4.7 → 3.5 → 2.3 → 1.0 비트).
  매 실행 level_bits 를 확인하세요. segment_eval.py 가 경고를 띄웁니다.
```

🚨 **이전 판의 결론 하나를 철회했습니다.**
```
"충돌률을 결정하는 건 층 수가 아니라 유효 비트다 (−0.96 vs −0.75)"
   → 버그가 만든 착시였습니다. 패치 후 −0.988 vs −0.986 으로 사실상 같습니다.
   → 다만 유효 비트는 계속 기록해야 합니다. 둘이 갈라지는 순간이 곧 붕괴입니다.
```

### 실행은 래퍼를 쓰세요
```bash
scripts/grid_mac.sh train experiment=rkmeans_train_flat "data_dir='<절대경로>'" ...
```
MPS 설정, dataloader 워커/타임아웃, experiment마다 다른 설정 경로를 자동 처리합니다.
전체 명령 예시는 `docs/08_파이프라인_완주기록.md` 6절에 있습니다.

### 🚨 코드북 학습은 max_steps=300 으로
```bash
scripts/grid_mac.sh train experiment=rkmeans_train_flat ... trainer.max_steps=300
```
GRID 기본값은 30입니다. 배치 2048 · 아이템 12,101개면 한 바퀴가 6배치라
30스텝은 약 5에폭뿐이라 k-means 가 덜 수렴합니다.

셔플 시드 패치를 적용하면 같은 시드는 같은 결과가 나오므로 "실행 간 변동" 문제는
없어집니다. 그래도 300을 권하는 이유는 **수렴 품질** 때문입니다.
L 이나 데이터가 바뀌면 코드북은 어차피 새로 학습되므로, 조건 간 비교에서는
각 조건이 충분히 수렴해 있어야 비교가 성립합니다.

비용은 실행당 252초 → 598초 (맥 기준 10분).

## 9. 핵심 사실 요약 (재조사 불필요)

```
[TIGER]
· NeurIPS 2023, Google DeepMind. 공식 코드 없음
· 1,300만 파라미터. 메모리 1~2GB면 충분 (병목은 시간)
· Beauty Recall@10 +0.15% / NDCG@10 +17.43%
  → "많이 맞히는" 게 아니라 "순위를 잘 매기는" 모델
· 콜드스타트 강점은 ε로 자리를 강제 예약한 결과

[GRID = 우리 베이스]
· Snap Research. TIGER 재현도 1위 (Recall@10 −0.5%)
· 어블레이션 8종: 슬라이딩윈도우 42% / 유저토큰은 빼는 게 나음 /
  RK-Means > RQ-VAE / 제약 빔서치가 오히려 손해
· 라이선스: Snap 비상업 연구 전용 (랩 연구·논문은 허용)

[Ghost]
· LC-Rec 기반, Qwen2.5-3B. 인기편향 원인 규명 + SKT/AUO
· Tail HR@10 +63.91%, 노출 43:1 → 1.6:1, 전체 정확도 −7.46%
· 데이터로 검증: tail 38,613개 100% head 접두사 상속
· 맥에서는 실행 어려움 (Qwen 3B + DeepSpeed 2GPU)

[연구 주제 근거]
GRID:       "층 늘리면 하락" (전체 평균만)
VarLenRec:  "인기 짧게, 비인기 길게" (구간별)
SA²CRQ:     "인기 길게, 비인기 짧게" (정반대)
→ 겹치는 구간이 L=4 하나뿐. L=2,3을 구간별로 본 사람 없음
→ Ghost가 실제로 인기 5토큰/비인기 7토큰 쓰고 Tail +63.91% 냄 (VarLenRec 편)
```
