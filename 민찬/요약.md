**파이프라인을 맥에서 끝까지 돌렸고, 그 과정에서 GRID 자체 버그 3건을 찾아 고쳤으며,

## 알아낸 것 4가지

### 1. 맥에서 TIGER 학습은 불가능합니다

```
Step 3 코드북 학습  3분      ✅        Step 5 TIGER 학습  스텝당 27초  ❌
Step 4 SID 생성    15초      ✅        → 32만 스텝 = 약 100일
Step 6 추론        1분 32초  ✅
```

**Step 3·4·6은 맥에서 개발하고 Step 5만 GPU에서 돌리면 됩니다.**
→ 랩 GPU 사양 확인이 지금 유일한 병목입니다.

### 2. GRID 코드에 버그 3건 — 특히 세 번째

```
① 쓰기 시 상위 폴더를 안 만듦        → 첫 실행이 무조건 실패
② 단일 프로세스인데 분산용 barrier 호출 → 추론 단계에서 죽음
③ 🚨 데이터 셔플에 시드가 안 넘어감   → 학습이 재현되지 않음
```

③이 가장 위험합니다. ①②는 에러를 내며 죽지만 **③은 조용히 틀립니다.**
같은 명령을 두 번 쳐도 코드북이 달라져서, 충돌률이 3.7%와 63.3%로 갈렸습니다.

원인은 `tf.data`의 `shuffle()`에 시드를 안 넘긴 것. GRID의 `seed_everything(42)`는
파이썬·NumPy·PyTorch만 잡는데 **데이터 로딩이 TensorFlow**라 새어나갔습니다.
고친 뒤 같은 시드는 SID 텐서가 비트 단위로 동일합니다.

### 3. 충돌은 인기/비인기를 가리지 않습니다 ← 제 가설이 틀렸습니다

```
층 수(L)      2       3       4       5
Beauty     62.4%   13.7%    5.5%    1.5%
Sports     71.4%   19.8%    6.9%    3.3%
Toys       62.0%   10.7%    3.3%    2.8%

TAIL − HEAD 충돌률 차이   평균 +0.27%p  (34회)
```

"비인기 아이템이 더 많이 뭉개져서 추천이 안 된다"고 봤는데 아니었습니다.
L을 하나 바꾸면 충돌이 수 배씩 뛰는데 구간 차이는 0.27%p입니다.

**→ 나중에 "층을 줄여 비인기 성능이 떨어졌다"는 결과가 나와도 충돌 탓으로 돌릴 수 없습니다.**
용의자 하나를 지운 셈이라 해석이 오히려 깔끔해집니다.

데이터셋 간 차이는 아이템 수로 설명됩니다. Sports가 18,357개로 가장 많아
필요 비트(log₂ 아이템수)가 높고 여유가 적어 더 충돌합니다.

### 4. COLD 실험은 방식을 바꿔야 했습니다

원래 계획한 "시간 기준 분할"은 불가능합니다. GRID·Ghost 데이터 **둘 다 타임스탬프가 없습니다.**

대신 아이템 10%를 학습에서 통째로 빼는 방식으로 만들었습니다.
검증 결과 학습·검증에 COLD 등장 0회, 테스트에서는 정답 위치에만 등장합니다.

⚠️ 논문에 쓸 때 구분 필요 — 이건 "학습에서 못 본 아이템"이지 "시간이 흐르며 새로 등장한 아이템"이 아닙니다.
