# 2. 정확도 지표

## Recall@10 — "10개 안에 넣었나"

```
유저 A:  정답이 3등에 있음     →  1점
유저 B:  정답이 10개 안에 없음  →  0점
유저 C:  정답이 9등에 있음     →  1점

Recall@10 = (1 + 0 + 1) / 3 = 0.667
```

**순위는 안 봅니다.** 3등이든 10등이든 똑같이 1점.

**실제 숫자로 읽으면**
```
Beauty  Recall@10 = 0.0648
→ 유저 100명 중 약 6.5명에게만 정답을 10개 안에 넣었다
```
상품이 1만 2천 개인데 10개만 보여주고 맞혀야 하니 이 정도가 정상입니다.

> ⚠️ **Recall@K = HR@K (Hit Rate)** 입니다. 정답이 1개뿐이라 같은 값이 됩니다. 논문마다 다르게 부릅니다.

## NDCG@10 — "몇 등에 넣었나까지"

순위를 반영합니다. 점수는 `1 / log₂(순위 + 1)`.

```
정답이 1등   →  1.000점
정답이 2등   →  0.631점
정답이 3등   →  0.500점
정답이 5등   →  0.387점
정답이 10등  →  0.289점
정답 없음    →  0점
```

**항상 Recall보다 작거나 같습니다.**
```
Beauty  Recall@10 = 0.0648
        NDCG@10   = 0.0384   ← 더 작음 ✓
```

## 🎯 이 둘의 차이가 중요한 이유

```
TIGER의 Beauty 결과:
   Recall@10  +0.15%   ← 맞히는 개수는 그대로
   NDCG@10   +17.43%   ← 맞힌 걸 더 앞에 놓음

→ "새 정답을 찾아낸" 게 아니라 "순위를 잘 매긴" 모델
```

**우리 목표(안 뜨던 걸 뜨게 하기)는 Recall을 올려야 하는 일입니다.**

# 3. 다양성·노출 지표

## Coverage — "카탈로그를 얼마나 쓰나"

```
Coverage = 한 번이라도 추천된 아이템 수 / 전체 아이템 수

0.30 → 상품의 30%만 누군가에게 추천됐다
       나머지 70%는 아무에게도 안 보여졌다
```

## Entropy@K — "얼마나 여러 카테고리에 흩어졌나"

```
추천 A:  샴푸 샴푸 샴푸 샴푸 샴푸 ...        →  Entropy 낮음 (0에 가까움)
추천 B:  샴푸 립스틱 네일 향수 마스크팩 ...  →  Entropy 높음
```

**TIGER 실측**
```
T = 1.0  →  Entropy@10 = 0.76
T = 2.0  →  Entropy@10 = 1.38   (거의 2배 다양)
```

## Gini 계수 — "노출이 몇 개에 쏠렸나"

```
0 = 완전 균등 (모든 아이템이 똑같이 노출)
1 = 완전 독점 (한 아이템이 전부 차지)

낮을수록 좋습니다.
```

# 4. 공정성 지표 (CRAB 논문에서 사용)

먼저 **GU (Group Unfairness)** 를 알아야 합니다.

아이템을 인기도로 그룹을 나눕니다 (상위 5%, 다음 5%, …).

```
GU(그룹) = (그 그룹이 추천에 나온 비율) − (그 그룹이 과거 데이터에 나온 비율)

GU > 0  →  과다 추천
GU < 0  →  과소 추천
GU = 0  →  과거와 똑같은 비율
```

**예시**
```
인기 상위 5%:  추천 30%, 과거 12%  →  GU = +0.18  (과다)
인기 하위 5%:  추천  1%, 과거  6%  →  GU = −0.05  (과소)
```

## MGU (Mean Group Unfairness)
```
MGU = 모든 그룹의 |GU| 평균
→ "전체적으로 얼마나 어긋나 있나"       낮을수록 좋음
```

## DGU (Disparity Group Unfairness)
```
DGU = (가장 과다 추천된 그룹) − (가장 과소 추천된 그룹)
    = 0.18 − (−0.05) = 0.23
→ "가장 유리한 그룹과 불리한 그룹의 격차"   낮을수록 좋음
```

## 🚨 DGU/MGU의 함정 — 반드시 알아야 합니다

```
DGU = 0 이라는 건?
   → 추천 분포 = 과거 상호작용 분포
   → "과거와 똑같이 추천한다"

그런데 과거 상호작용 자체가 옛 시스템이 만든 것입니다
   → DGU를 0으로 만드는 건 "옛 편향을 충실히 재현"하는 것
```

**DGU/MGU는 "과거 대비 왜곡"을 재지, "실제로 롱테일에 도달했는가"를 재지 않습니다.**

Ghost가 노출 비율(43:1 → 1.6:1)을 **따로** 잰 이유가 여기 있습니다.
CRAB은 이걸 안 쟀습니다.

# 5. 기타 지표

| 지표 | 설명 | 방향 |
|---|---|---|
| **AUC** | 좋아할 것과 안 좋아할 것을 얼마나 잘 구분하나 (0.5 = 찍기) | 높을수록 좋음 |
| **표준오차 ±** | 같은 실험을 여러 번 돌렸을 때 흔들리는 폭 | 작을수록 신뢰 |
| **환각률** | 카탈로그에 없는 번호를 생성한 비율 | 낮을수록 좋음 |
| **코드북 활용률** | 256개 코드 중 실제로 쓰인 개수 | 높을수록 좋음 |
| **충돌률** | 여러 아이템이 같은 번호를 갖는 비율 | 낮을수록 좋음 |

## 표준오차를 왜 봐야 하나

```
Beauty  Recall@5 = 0.0441 ± 0.00069   (3번 돌린 결과)

→ 대략 0.0434 ~ 0.0448 사이에서 왔다갔다 합니다

우리가 개선해서 0.0448이 나왔다면?  →  흔들림 범위 안. 개선이라 말할 수 없음
0.0470이 나왔다면?                  →  흔들림의 4배 밖. 진짜 개선일 가능성 높음
```

**그래서 시드를 여러 개 돌려야 합니다.** 한 번 좋은 숫자가 나와도 우연일 수 있습니다.

# 6. 모델 구조 용어

## Semantic ID (의미 번호)
```
아이언맨  →  (12, 7, 3, 1)
             └┬┘ └┬┘└┬┘ └┬┘
            큰분류 중분류 소분류 충돌방지

앞자리가 큰 카테고리, 뒤로 갈수록 세밀합니다.
비슷한 아이템은 앞자리를 공유합니다.
```

## RQ-VAE (잔차 양자화)
```
1단계:  원본에서 큰 덩어리를 떼어냄       →  남은 것(잔차) 큼
2단계:  남은 것에서 또 떼어냄            →  잔차 중간
3단계:  또 떼어냄                        →  잔차 작음

각 단계에서 "가장 가까운 코드워드"를 골라 그 번호를 씁니다.
```

## 코드북 / 코드워드
```
코드북   =  선택지 목록 (보통 256개)
코드워드 =  그 안의 하나

각 단계마다 별도 코드북을 씁니다.
→ 256 × 256 × 256 = 1,677만 개 조합 표현 가능
```

## 빔서치 (Beam Search)
```
번호를 한 칸씩 쓸 때, 후보가 매 칸 256개씩 생깁니다
전부 따라가면 폭발하니까 → 상위 N개만 남기고 버립니다

N = 빔 크기.  TIGER는 20~30 정도를 씁니다
```

## Trie 제약 디코딩
```
"실제 카탈로그에 있는 조합만 생성하게" 막는 장치

없으면 → 없는 상품 번호를 만들어냄 (= 환각)
```

## Teacher Forcing
```
학습할 때:  정답을 보면서 다음을 예측
추론할 때:  자기가 만든 걸 보면서 다음을 예측

→ 이 차이 때문에 오차가 누적됩니다 (exposure bias)
```

## Leave-one-out
```
유저 시퀀스 [a, b, c, d, e]

학습:  [a, b, c]  (마지막 2개 제외)
검증:  d          (뒤에서 두 번째)
테스트: e          (마지막)
```

## 슬라이딩 윈도우 증강
```
유저 이력 [a, b, c, d, e]

증강 없음:  입력 [a,b,c,d] → 정답 e            (예시 1개)

증강 있음:  입력 [a]       → 정답 b
           입력 [a,b]     → 정답 c
           입력 [a,b,c]   → 정답 d
           입력 [a,b,c,d] → 정답 e            (예시 4개)
```
**GRID 논문: 이게 있고 없고가 성능 42% 차이를 만듭니다.**

# 7. 구간 용어 (우리 실험에서 쓸 것)

```
HEAD   인기 상위 20%      상호작용이 많은 아이템
BODY   중간 60%
TAIL   하위 20%           상호작용이 적은 아이템 (학습 데이터에는 있음)
COLD   신규               학습 데이터에 아예 없는 아이템
```

## ⚠️ TAIL과 COLD는 다릅니다

| | **TAIL (비인기)** | **COLD (신규)** |
|---|---|---|
| 정의 | 학습 데이터에 **있지만** 상호작용이 적음 | 학습 데이터에 **없음** |
| TIGER 성능 | 나쁨 | **거의 0** |
| 해법 방향 | 토큰 분포 균형 | 식별자 설계, 도달 가능성 |
| RL 효과 | 🟢 도움 | 🔴 오히려 해로울 수 있음 |

**팀이 "비인기·신규"를 섞어서 말하는데, 구분해야 합니다.**

## 논문마다 구간 정의가 다릅니다

```
Ghost:      누적 상호작용 80% 지점으로 head/tail 이분
            → 실제 결과 head 18.6~19.3%

VarLenRec:  아이템 개수 상위 20% / 중간 60% / 하위 20%

MMQ:        누적 노출 상위 25% / 하위 25%
```

**우리는 VarLenRec 방식(20/60/20)을 씁니다.** 그쪽과 대조하기 위해서입니다.
그리고 Ghost의 실제 비율(19%)과 거의 같아서 비교도 가능합니다.

# 8. 진단 용어 (2026-08 실험에서 추가)

`sweep_layers.py` 와 `segment_eval.py` 가 내는 값들입니다.

## 충돌 (Collision)

**서로 다른 아이템이 똑같은 SID를 받는 것.**

```
립스틱 A  →  <a_143> <b_47> <c_88>
립스틱 B  →  <a_143> <b_47> <c_88>   ← 같음
```

택배 주소가 겹쳐서 어느 집인지 모르는 상황입니다.
모델이 이 주소를 생성해도 A인지 B인지 정할 수 없습니다.

**GRID는 뒤에 자릿수를 하나 더 붙여 땜빵합니다** (중복 제거 자릿수).
A는 `...0`, B는 `...1`. 그런데 이 칸은 의미 없는 일련번호라
모델 입장에서는 찍기입니다.

```
실측 (Beauty, 코드북 256, 시드 3개 평균)
   층 2개 → 62.4%      층 5개 → 1.5%
   층 3개 → 13.7%      층 6개 → 0.9%
   층 4개 →  5.5%      층 8개 → 0.4%
```

## 층 붕괴 (Layer Collapse)

**한 자리가 사실상 한 가지 값만 뱉는 상태.** 칸은 있는데 일을 안 합니다.

```
정상  3번째 칸이 7.4비트  →  아이템을 여러 갈래로 나눔
붕괴  3번째 칸이 0.6비트  →  거의 전부 같은 값. 안 나눔
```

주소로 치면 **모든 집의 "동" 칸에 "역삼동"만 적혀 있는** 상태입니다.

🚨 **코드워드 개수로는 안 잡힙니다.** 붕괴한 실행도 256개를 "다 씁니다".
한 코드워드가 아이템의 95%를 삼키고 나머지 255개가 1개씩 갖는 식이라,
개수는 멀쩡해 보입니다. **반드시 엔트로피로 봐야 합니다.**

## 엔트로피 / 유효 비트 (Effective Bits)

**비트 = 몇 가지를 구별할 수 있는지를 로그로 센 것.**

```
1비트 = 2가지     3비트 = 8가지     8비트 = 256가지
```

스무고개 질문 개수라고 보면 됩니다. 예/아니오 8번이면 256개 중 하나를 집어냅니다.

```
한 자리가 코드워드 256개를 완벽히 고르게 쓰면   8.0비트
실제로는 쏠림이 있어서                          7.4비트쯤
붕괴하면                                        0.6비트
```

**유효 비트 = 모든 자리의 비트 합.** 주소 체계 전체의 구별 능력입니다.

```
아이템 12,101개를 전부 구별하려면 최소 log₂(12,101) = 13.6비트 필요
그보다 적으면 비둘기집 원리로 반드시 충돌이 납니다

L=2 → 15.0비트 (아슬아슬)  →  충돌 62%
L=3 → 22.4비트             →  충돌 14%
```

⚠️ **정상 학습되면 유효 비트 ≈ L × 7.4** 라서 층 수와 거의 같은 값입니다.
둘이 갈라지는 순간이 곧 "붕괴한 실행"입니다. 그래서 둘 다 기록합니다.

# 9. 통계 용어 (결과를 읽을 때)

## %p (퍼센트 포인트)

퍼센트끼리 뺀 값. **%와 다릅니다.**

```
어제 4%  →  오늘 5%

"1%p 올랐다"    ← 그냥 뺀 값 (5 − 4)
"25% 올랐다"    ← 비율로 본 값 (1 ÷ 4)
```

## 상관계수

두 값이 같이 움직이는 정도. −1 ~ +1.

```
+1.0  완벽히 같이 늘어남    (키가 크면 몸무게도 큼)
 0.0  아무 상관 없음
−1.0  완벽히 반대로 움직임  (계단을 오를수록 남은 계단이 줆)
```

우리 실측: 층 수 vs 충돌률 = **−0.988** (거의 완벽하게 반대)

## p값

**"아무 차이가 없는데도 이 정도로 치우칠 확률."**

```
공정한 동전을 18번 던졌는데 앞면이 14번 나왔다.
이상한 동전일까, 그냥 운일까?

p = 0.031  →  공정한 동전이라도 3.1% 확률로 이렇게 나온다
              드무네 → "차이가 있는 것 같다"
```

보통 0.05보다 작으면 "우연으로 보긴 어렵다"고 판단합니다.

## 검정이 서로 다른 답을 낼 때

같은 데이터를 **다른 방식으로** 보기 때문입니다.

```
부호검정   방향만 봄 (높았나 낮았나)          p=0.031  차이 있음
윌콕슨     방향 + 순위                        p=0.038  차이 있음
t검정      방향 + 실제 크기까지               p=0.131  차이 없음
```

t검정만 다른 답을 낸 건 **크기**를 보기 때문입니다.
방향은 일관됐지만 차이가 0.23%p 밖에 안 됐습니다.

> **엇갈릴 때는 크기를 보세요.** 통계적으로 유의해도 크기가 무의미하면
> 실험 해석을 바꾸지 못합니다.

## 신뢰구간

**"진짜 값은 아마 이 범위 안에 있을 것"** 이라는 구간.

```
95% 신뢰구간 [−0.11%p, +0.46%p]
              ↑ 0이 이 안에 들어 있음
              → "진짜로는 차이가 0일 수도 있다"
```

## 효과 크기 — 가장 중요합니다

**"통계적으로 유의한가"보다 "실무적으로 의미 있는 크기인가"가 먼저입니다.**

```
TAIL이 HEAD보다 0.23%p 더 충돌  (p=0.031 로 유의)

그런데 층을 하나 줄이면 충돌이 이만큼 뜁니다:
   1.5%  →  5.5%  →  13.7%  →  62.4%
```

서울에서 부산 가는데 KTX냐 자전거냐를 고르는 상황에서
"신발끈을 세게 묶었냐"를 따지는 격입니다.
