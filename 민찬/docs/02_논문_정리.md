# 1. TIGER — 이 분야의 원점 ✅ 원문 정독

**[Recommender Systems with Generative Retrieval](https://arxiv.org/abs/2305.05065)**
Rajput 외 12명 · **Google DeepMind** · NeurIPS 2023

## 구조

```
[1단계] 아이템 콘텐츠(제목·가격·브랜드·카테고리) → 문장으로 조합
        → Sentence-T5 (768차원)
        → RQ-VAE: 인코더 512→256→128→잠재 32차원
                  3단계 잔차 양자화, 각 코드북 256개
        → (c₁,c₂,c₃) + 충돌방지 c₄  =  길이 4

[2단계] T5X 프레임워크
        어휘: 코드워드 1,024개(256×4) + 유저 토큰 2,000개
        인코더 4층 / 디코더 4층, 헤드 6개, MLP 1024, 입력 128
        파라미터 약 1,300만
```

## 놓치기 쉬운 설계 결정 3가지

**① 레벨마다 별도 코드북**
> 잔차의 norm이 레벨이 올라갈수록 작아지므로, 레벨마다 다른 granularity를 허용하기 위해

**② 코드북 붕괴를 k-means 초기화로 방지**
> 첫 학습 배치에 k-means를 적용해 centroid를 초기값으로 사용

**③ 20k epoch 학습해서 코드북 사용률 80% 이상 확보**
```
손실: L = L_recon + L_rqvae,  β = 0.25
최적화: Adagrad, lr 0.4, batch 1024
```

## 데이터

| | 유저 | 아이템 | 평균 길이 | 중앙값 |
|---|---|---|---|---|
| Beauty | 22,363 | 12,101 | 8.87 | 6 |
| Sports | 35,598 | 18,357 | 8.32 | 6 |
| Toys | 19,412 | 11,924 | 8.63 | 6 |

리뷰 5개 미만 유저 제거 · leave-one-out · 학습 시 히스토리 20개 제한

## 결과

| | Recall@5 | NDCG@5 | Recall@10 | NDCG@10 |
|---|---|---|---|---|
| Beauty | 0.0454 (+17.31%) | 0.0321 (+29.04%) | 0.0648 **(+0.15%)** | 0.0384 (+17.43%) |
| Sports | 0.0264 (+5.22%) | 0.0181 (+12.55%) | 0.0400 (+3.90%) | 0.0225 (+10.29%) |
| Toys | 0.0521 (+12.53%) | 0.0371 (+21.24%) | 0.0712 (+1.71%) | 0.0432 (+14.97%) |

> 🚨 **Beauty Recall@10 개선이 +0.15%입니다.** NDCG는 크게 오르는데 Recall은 거의 안 오릅니다.
> **"더 많이 맞히는" 게 아니라 "순위를 잘 매기는"** 모델입니다.

## 🚨 재현 시 주의 — Table 1과 Table 9가 다릅니다

```
Table 1 (본문 보고):  Recall@10 0.0648,  NDCG@10 0.0384
Table 9 (3시드 평균):  Recall@10 0.0642 ± 0.00092,  NDCG@10 0.0374 ± 0.00061
```
**재현 목표는 Table 9로 잡아야 합니다.**

## 콜드스타트 실험 — ε로 강제 주입하는 방식

```
1. Beauty 테스트 아이템의 5%를 학습에서 제거 → unseen
2. 학습 후 RQ-VAE로 모든 아이템(unseen 포함) SID 생성
3. 앞 3토큰이 같은 unseen 아이템을 후보에 포함
4. ★ ε = "unseen 최대 비율" 하이퍼파라미터로 자리 예약
```
**모델이 스스로 찾는 게 아니라 자리를 비워두는 겁니다.**

## 다양성 실험

```
T=1.0  →  Entropy@10 0.76
T=2.0  →  Entropy@10 1.38
```
> SID의 첫 토큰을 샘플링하면 거친 카테고리에서, 두/세 번째를 샘플링하면 카테고리 내에서 검색

## 환각 (4.5절)

```
가능한 SID: 256⁴ ≈ 4조     실제 아이템: 10K~20K
그런데 모델이 거의 항상 유효 ID를 예측

invalid 비율:  top-10에서 0.1~1.6%,  top-20에서 0.3~6%
```

## 🎯 저자가 남긴 숙제

> invalid 토큰을 처리하는 확장 하나는 **prefix matching**이다. (…) RQ-VAE의 계층적 성질 덕분에, 접두사 매칭은 모델이 아이템 인덱스 대신 **카테고리를 예측한 것**으로 볼 수 있다. 이런 확장이 **recall/NDCG를 더 개선할 수 있다.** 우리는 이를 미래 과제로 남긴다.

**3년이 지났는데 Ghost와 Reachability 논문이 이 축을 돌고 있습니다.**

# 3. Ghost — 편향 원인 규명 ✅ 원문 정독 + 코드 검증

**[Echoes in Filter Bubble: Diagnosing and Curing Popularity Bias in Generative Recommenders](https://arxiv.org/html/2605.16825v1)**
Yin, Zhu, Huo, Liu, Chen, Wang, **Shirui Pan, Chengqi Zhang** · 2026.05
[github.com/Esperanto-mega/Ghost](https://github.com/Esperanto-mega/Ghost)

## 진단 — 이 논문의 진짜 가치

### 원인 ① 그래디언트 기아
```
인기 토큰:   정답으로 자주 등장  →  큰 양(+) 업데이트  →  유저 선호 쪽으로 끌려감
비인기 토큰: softmax 분모에서 "오답 후보"로만 등장
             →  계속 음(−) 업데이트만  →  계속 밀려남
```
> 롱테일 토큰은 **점근적으로 밀어내는 업데이트만** 받는다

### 원인 ② 분기점에서의 기하급수적 억제
```
분기점 1개 통과 확률:  γ
분기점 z개면:          γ^z      →  O(γ_min^z)

측정된 격차:  LC-Rec에서 인기/비인기 HR@10 최대 45배
```

## 처방 — 두 부품

### SKT (Skeleton-Founded Tokenization)
```
비인기 아이템이 "의미적으로 가장 가까운 인기 아이템의 앞부분을 통째로 물려받음"
그 뒤에 구별용 토큰만 추가

→ 분기점을 (L^h + 1) 단계로 미룸
→ 여러 단계의 기하급수적 억제를 단일 단계 차이로 축소
```

### AUO (Asymmetric Unlikelihood Optimization)
```
각 아이템마다 "임베딩은 비슷한데 SID는 다른" 상대를 골라 명시적으로 억제

L = L_NLL + α · L_AUO      (α = 0.1 최적)
```

## 결과 (LC-Rec 대비)

| 지표 | 결과 |
|---|---|
| Tail HR@10 | 🟢 **+63.91%** |
| Tail NDCG@10 | 🟢 **+70.66%** |
| MGU (불공정성) | 🟢 **−55.76%** |
| 전체 HR@10 | 🔴 **−7.46%** |
| 전체 NDCG@10 | 🔴 −6.34% |
| CNS (종합) | 🟢 +16.81% |

**노출 균형**
```

Ghost:   인기 15,372개  vs  비인기  9,400개   →  1.6 : 1
```

## 🎯 우리가 데이터로 검증한 것

```
tail 아이템의 앞 4토큰이 head 접두사와 일치하는가?

Instruments   8,075개  →  100.0%
```

# 4. VarLenRec vs SA²CRQ — 정면 충돌 ⚠️

## VarLenRec [2605.17779](https://arxiv.org/html/2605.17779)

```
Head(상위20%) / Body(60%) / Tail(하위20%)로 나눠 L ∈ {4,6,8,10} 실험

Head:  ID가 길수록 성능 단조 감소.  L=4가 최적
Tail:  ID가 길수록 성능 단조 증가

이론:  협업 신호  I_collab(p) = α·log(1+θ·p)
      의미 ID    I_semantic(L) = γ·ln(L)
      → 인기는 협업 신호 충분 → 짧게
        롱테일은 부족 → 콘텐츠로 채워야 → 길게

정리 1:  L* = C · p^(−α/γ)
```
결과: NDCG@10 +8.3%, 충돌률 12.7% → 3.2%

## SA²CRQ [2602.23978](https://arxiv.org/abs/2602.23978)

```
Head:  짧은 코드에서 ID 충돌 → 구별 안 됨 → 길게
Tail:  긴 1:1 매핑은 과적합 → 고립 → 짧게

JD.com 산업 데이터 (쿼리 1800만 / 아이템 500만)
   Tail 커버리지  509 → 914  (+79%)
   R@2k          0.6448 → 0.7231  (+12.1%)
   환각률        0.2514 → 0.1808  (−28%)
   온라인 A/B    전환율 +0.13%
```

## 🔍 모순의 정체

```
VarLenRec이 묻는 것:  "tail을 정확히 표현하려면?"   →  길게
SA²CRQ가 묻는 것:     "tail을 일반화시키려면?"      →  짧게

핵심 차이 = 고유성 vs 공유
   긴 ID  →  고유해짐  →  정확하지만 고립
   짧은 ID →  공유됨    →  일반화되지만 구별 안 됨
```

## 🎯 Ghost가 제3의 답

```
Ghost SKT:  앞은 head와 공유  (SA²CRQ의 목표)
            뒤는 자기 것       (VarLenRec의 목표)

그리고 실제로 head 5토큰 / tail 7토큰 → VarLenRec 편
        Tail HR@10 +63.91% 달성
```

> **개별 토큰을 봤다고 조합이 보장되지 않는다.**
> 의미 번호 생성은 **"학습된 이산 토큰 경로 공간 위의 제약된 검색"** 이지 열린 추론이 아니다.

# 6. Spotify GLIDE — 실서비스에서 목표 달성 ✅ 원문 정독

**[Deploying Semantic ID-based Generative Retrieval for Large-Scale Podcast Discovery at Spotify](https://arxiv.org/html/2603.17540v1)** · 2026.03

## 구성
```
백본:  Llama 3.2 1B
입력:  ① SID 시퀀스 히스토리
       ② 자연어 유저 컨텍스트 (로케일, 토픽)
       ③ CF 임베딩을 soft prompt 토큰 1개로 주입
       ④ 태스크 지시문
SID:   Residual K-Means (K=256, M=4) → 토큰 1,024개
디코딩: 빔서치 30 beams, 처리량 8배 개선
```

## 🎯 친숙/낯선 멀티태스크 — 핵심 기법

```
28일 창, 10분 청취 기준으로 3분류
   Habitual                최근 28일 10분 이상
   Non-habitual familiar   들어봤지만 최근엔 아님
   Non-habitual unfamiliar 한 번도 안 들음   ← exploration 대상

동적 제어 토큰으로 학습
→ 추론 시 토큰만 바꾸면 재학습 없이 방향 전환
```
효과: 낯선 모드 Recall@30 **+11.8%**, 친숙 모드 +4.9%

## 인기 편향 완화 3종
```
① Cross-surface sampling   여러 지면에서 샘플 → 피드백 루프 감소
② Exploration upweighting  무작위 배치 스트림에 높은 가중치
③ Popularity capping       에피소드당 학습 예시 수 상한
```

## 결과

**오프라인**
```
Recall@30            +29.9%
NDCG@30              +31.2%
낯선 콘텐츠 NDCG@30   +35.4%   ← exploration이 제일 크게 올랐습니다
```

**온라인 A/B (21일, 약 2천만 노출)**
```
비습관적 스트림/유저     +5.4%   (α<0.01)
신규 쇼 비습관적 스트림  +14.3%  (α<0.01)
GLIDE 후보 비중          약 34%
회귀 없음
```

## 실무 교훈

**① R-KMeans > RQ-VAE (+9.52%)**
```
같은 SID를 공유하는 에피소드의 임베딩 코사인 유사도
   R-KMeans  0.856   ← 충돌해도 의미 있는 대안
   R-LFQ     0.713
   RQ-VAE    0.657   ← 엉뚱한 것끼리 묶임
```
> RQ-VAE는 **코드북 붕괴, 초기화 민감성, 보조 손실 의존** 때문에 프로덕션에서 운영상 취약하다

**② 탐욕 디코딩은 Recall@30 −27.07%.** 빔서치 필수.

**③ 🚨 오프라인 지표가 인기 편향에 속습니다**
> LLM 판정자와 인간 평가자가 같은 변형을 선호했는데, **오프라인 recall은 다른 모델을 선호**했다. 분석해보니 recall이 선호한 변형이 **더 강한 인기 편향**을 보였다.

## ⚠️ 편향의 원인이 여기 있습니다
> 여러 에피소드가 같은 SID로 매핑되면 **인기 기반 결정론적 타이브레이커**로 가장 인기 있는 것을 선택한다
