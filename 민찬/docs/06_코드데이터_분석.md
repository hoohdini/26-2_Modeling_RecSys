```

```

## 1-3. 그럼 슬라이딩 윈도우 증강은 어디에?

GRID 논문은 *"증강 유무가 42% 차이를 만든다"* 고 했는데,
```
데이터:  유저당 1행 → 증강 없음
코드:    pre_processing.py, iterators.py, dataloading.py 어디에도 증강 로직 없음
```

**답은 `label_function.py`에 있습니다.**

```
Identity            패딩 아닌 모든 토큰을 라벨로
                    → 시퀀스 [a,b,c,d,e] 한 번에
                      a→b, b→c, c→d, d→e 를 동시에 학습
                    = 슬라이딩 윈도우와 같은 효과

NextKTokenMasking   마지막 K개 토큰만 라벨로
                    → 예시 1개
```

> 🚨 **GRID 논문의 "증강 유무"는 이 두 라벨 함수의 차이일 가능성이 높습니다.**
> 재현할 때 `label_function` 설정을 반드시 확인하세요. 이게 42%를 가릅니다.

## 1-5. ✅ P5 누수 우려는 해소됐습니다

`pre_processing.py` 원문 확인:
> dataset config의 `id_map`에 기반해 sparse id를 semantic id로 매핑한다. `id_map`은 D × N 텐서이며 N은 고유 아이템 수, D는 계층 레벨 수다.

```
원래 아이템 ID  →  배열 인덱스로만 사용
                  ↓  id_map 조회
모델 입력      →  Semantic ID

→ P5의 순차 ID가 모델에 들어가지 않음
→ SentencePiece 서브워드 공유가 일어날 수 없음
```

TIGER 부록 D가 지적한 누수 메커니즘이 **작동할 여지가 없습니다.**

## 2-4. 🎯 부수적 발견 2가지

### ① 구간 정의 걱정이 해소됐습니다

```
Ghost 실제 head 비율:  18.6% / 19.3% / 19.2%
VarLenRec 기준:        20%

→ 사실상 같습니다. 비교 가능합니다.
```

Ghost는 *"누적 상호작용 80% 지점"* 으로 나누는데(`process_head-tail.py` 확인),
결과적으로 **아이템 개수의 약 19%** 가 head가 됩니다.

### ② Ghost는 VarLenRec 편입니다

```
Ghost:      head 5토큰(짧게)  /  tail 7토큰(길게)
VarLenRec:  head 짧게         /  tail 길게        ← 일치 ✅
SA²CRQ:     head 길게         /  tail 짧게        ← 반대 ❌
```

**그리고 Tail HR@10 +63.91%를 달성했습니다.**
→ VarLenRec 가설을 지지하는 실증 사례입니다.

# 3. Ghost 코드 분석

## 3-1. 파일 구성

```
warm_up.py          stage_1 (의미 접지, 태스크 5개)
finetune.py         stage_2 (추천 학습 + AUO)
data.py             데이터 로딩 + negative 선택 (45KB)
evaluate.py         Hit@k, NDCG@k (2KB)
collator.py         배치 구성
prompt.py           프롬프트 템플릿 (23KB)
RQ-KMeans/main.py   토크나이저
config/             DeepSpeed ZeRO 2/3 × bf16/fp16 6종
flops_profiler.out  연산량 프로파일
```

## 3-2. 학습 2단계

```bash
# stage_1.sh
torchrun --nproc_per_node=2  warm_up.py
   데이터셋 Instruments · lr 3e-5 · batch 8×2 · 4 epoch
   DeepSpeed + bf16
   태스크 5개: item2index, index2item, fusionseqrec, itemsearch, preferenceobtain
   → SID 토큰의 의미를 모델에게 가르치는 단계

# stage_2.sh
torchrun --nproc_per_node=2  finetune.py
   8 epoch · stage_1 체크포인트에서 이어받음
   --tasks seqrec
   --ul_alpha 0.1      ← AUO의 α (논문 최적값과 일치)
   --negative_k 5      ← 억제 대상 개수 (논문 최적값과 일치)
```

## 3-3. 슬라이딩 윈도우 증강 — Ghost는 코드에 있습니다

`data.py` → `_process_train_data()`
```python
token_items = self.remapped_inters[uid][:-2]      # 마지막 2개 제외
for i in range(1, len(token_items)):              # ← 슬라이딩 윈도우
    one_data["item"]   = token_items[i]           #   정답 = i번째
    history_tokens     = token_items[:i]          #   입력 = 0 ~ i-1
    history_tokens     = history_tokens[-self.max_his_len:]
```

**GRID와의 차이**
```
GRID:   데이터/라벨함수 설정으로 처리
Ghost:  코드에서 명시적으로 처리  →  커스텀 데이터를 쓰기 더 쉬움
```

## 3-4. 분할 — 표준 leave-one-out ✅

```python
학습:   inters[uid][:-2]  +  슬라이딩 윈도우
검증:   items[-2]         (뒤에서 두 번째)
테스트: items[-1]         (마지막)
```
TIGER, GRID와 동일합니다.

## 3-5. AUO의 negative 선택 — 논문보다 정교합니다

논문은 *"tail마다 유사한 head를 억제"* 라고만 썼는데 **코드는 양방향입니다.**

```python
# Head → Tail : 정답이 head면, 비슷한 tail을 억제
# Tail → Head : 정답이 tail이면, 비슷한 head를 억제
```

**선택 알고리즘** (`_init_hard_negative_pool_v2`)
```python
candidate_pool_size = 50

1. 임베딩 L2 정규화 후 내적으로 유사도 계산
2. 상위 50개 후보 추출                    ← "내용이 비슷한 것들"
3. 각 후보의 SID 접두사 일치 길이 계산
      for t1, t2 in zip(seq1[:4], seq2[:6]):
          if t1 == t2: match_len += 1
          else: break
4. sort(오름차순) 후 앞에서 negative_k개   ← "번호는 가장 다른 것들"
```

**= "내용은 비슷한데 번호는 완전히 다른" 아이템을 억제합니다.**

## 3-6. 🎯 SKT와 AUO가 맞물립니다 — 논문에 없는 발견

앞서 검증했듯 **tail의 앞 4토큰은 100% 어떤 head의 접두사입니다.**

```
정답이 tail 아이템 T 라면
   T의 앞 4토큰 = 어떤 head H의 앞 4토큰   (SKT 구조상 반드시)
        ↓
   H를 negative 후보로 평가하면 match_len = 4  (최댓값)
        ↓
   오름차순 정렬에서 맨 뒤로 밀림
        ↓
   ★ "자기 부모 head"는 억제 대상에서 자동 제외됩니다
```

**억제 대상은 "다른 가지에 있는, 내용만 비슷한 head"입니다.**
**SKT가 AUO의 안전장치 역할을 합니다.** 코드를 읽어야만 보이는 구조입니다.

## 3-7. UL 손실 구현

`finetune.py` → `ULTrainer.compute_loss`
```python
ul_loss_per_token = -torch.log(torch.clamp(1.0 - probs, min=1e-5))
total_loss = mle_loss + self.ul_alpha * ul_loss
```
논문 수식 `L_All = L_NLL + α·L_AUO` 와 일치합니다.

## 3-8. evaluate.py — 구간별 집계 없음 ✅

전문(2KB)을 읽었습니다.
```python
hit_k    →  상위 k개에 하나라도 맞으면 +1     (= Recall@K)
ndcg_k   →  res[i] / log2(i+2)               (표준 NDCG)

무효 ID  →  if seq not in all_items: scores[i] = -1000
             (제거가 아니라 맨 뒤로 "강등")
```

**head/tail 파일이 데이터에 있는데도 evaluate.py는 쓰지 않습니다.**
→ 논문의 `43:1 → 1.6:1` 분석은 별도 스크립트로 한 것이 확실합니다.
→ **우리가 구간별 집계를 붙일 자리가 여기입니다.**

# 4. 정리 — 확인된 사실

| 항목 | 결과 |
|---|---|
| GRID 데이터에 증강 있나 | ❌ **없음.** 유저당 1행. `label_function`으로 처리 |
| P5 누수가 GRID에 영향 | ❌ **없음.** semantic ID로 재매핑됨 (코드 확인) |
| GRID 층 수 실험 가능 | ✅ `num_hierarchies` 인자로 즉시 |
| Ghost SKT 접두사 상속 | ✅ **100%** (3개 데이터셋 38,613개 tail 전부) |
| Ghost 구간 정의 | ✅ 실제 19% ≈ VarLenRec 20%. **비교 가능** |
| Ghost 분할 방식 | ✅ 표준 leave-one-out |
| Ghost 구간별 평가 | ❌ **없음** → 우리가 붙일 자리 |
| SKT ↔ AUO 맞물림 | 🎯 **논문에 없는 구조 발견** |
| Mac에서 GRID 실행 | 🟢 **가능해 보임** (CUDA 패키지 미사용) |
| Mac에서 Ghost 실행 | 🔴 **어려울 것** (Qwen 3B + DeepSpeed 2GPU) |
