```
"비인기 아이템 추천이 좋아졌다"를 재는 공통 도구를 만들었습니다.

GRID에 묶여 있지 않습니다. 아래 4개만 있으면 어느 구현이든 같은 표가 나옵니다.
  ① SID 맵 (아이템 id → semantic ID)
  ② 예측  (유저 id → 추천 SID 상위 k개)
  ③ 정답  (유저 id → 정답 아이템 id)
  ④ 구간 정의 (scripts/item_segments.py 로 생성)

내는 것:
  정확도  구간별 HR@k, NDCG@k  + 표본 수 n + 95% 신뢰구간
  노출    구간별 추천 횟수, 노출 배율, HEAD:TAIL 노출비, Coverage, Gini
  진단    환각률, 코드북 활용률, SID 충돌률

🚨 신뢰구간을 꼭 같이 보세요

   HEAD 에서는 확실한 차이지만 TAIL 에서는 우연일 수 있습니다.

두 실행을 비교할 때는 --compare 를 쓰세요. 같은 유저를 짝지어 재기 때문에
신뢰구간 두 개를 눈으로 겹쳐 보는 것보다 훨씬 민감합니다.

  python scripts/segment_eval.py --compare 기준.json 비교.json

  구간         n      기준      비교        차이       95% 신뢰구간       p
  TAIL     4,024   0.0121   0.0169   +0.0048  [+0.0011, +0.0085]  0.012 ↑
  (↑ 는 신뢰구간이 0을 걸치지 않는다는 표시입니다)

노출 배율(lift) = 그 구간이 제 몫(아이템 수 비율)의 몇 배로 노출됐는가.
  1.00 이면 딱 제 몫, 2.00 이면 두 배, 0.10 이면 10분의 1.
HEAD:TAIL 노출비는 Ghost 논문이 43:1 → 1.6:1 로 보고한 것과 같은 값입니다.

🚨 부탁 하나: TAIL 과 COLD 를 구분해 주세요. 지금 팀에서 "비인기·신규"를 섞어

## ⑤ GRID 저장소에 버그 제보 (mju@snap.com)

```
GRID를 맥에서 돌리면서 코드 버그 3건을 찾았습니다.
맥 문제가 아니라 NVIDIA 다중 GPU 환경이 아니면 누구나 밟습니다.

① 쓰기 시 상위 폴더를 만들지 않아 첫 실행이 무조건 실패
   src/utils/file_utils.py : open_local_or_remote
   Hydra 가 실행마다 새 타임스탬프 폴더를 만드는데
   fs.open(path, "w") 는 그 폴더를 만들어 주지 않습니다.
   → metadata/restart_metadata.json 에서 FileNotFoundError

② 단일 프로세스인데도 분산 학습용 barrier 를 호출
   src/utils/inference_utils.py (3곳)
   if trainer.global_rank != None:  ← 단일 프로세스도 rank가 0이라 항상 참
   → "Default process group has not been initialized"

③ 🚨 데이터 셔플에 시드가 안 넘어갑니다 — 학습이 재현되지 않습니다
   src/data/loading/components/iterators.py (2곳)

     raw_dataset = raw_dataset.shuffle(buffer_size=128)   ← seed 인자 없음

   tf.data 의 shuffle() 은 시드를 안 주면 매 실행 무작위 시드를 뽑습니다.

   잡습니다. 데이터 로딩이 TensorFlow 라서 그대로 새어나갑니다.

   → 같은 명령을 두 번 쳐도 코드북이 달라집니다.

   수정 후 검증: 같은 명령 2회 → SID 텐서 비트 단위 완전 동일

## ⑥ 팀 전체 — 실행 관련 참고사항 3가지

```
1. 맥에서는 TIGER 학습(Step 5)을 못 돌립니다
   스텝당 27초 × 기본 320,000 스텝 ≈ 100일
   ⚠️ max_epochs: 10 이 설정에 있지만 발동하지 않습니다.
      학습 데이터셋이 무한 반복(UnboundedSequenceIterable)이라
      max_steps 가 실제 종료 조건입니다. 착각하기 쉽습니다.

   Step 3(코드북)·4(SID 생성)·6(추론)은 맥에서 몇 분이면 됩니다.

2. COLD(신규 아이템) 실험은 가능합니다. 단 "시간 기준"은 아닙니다
   GRID 데이터 필드: user_id · sequence_data · embedding · text
   Ghost 데이터도 유저→아이템 시퀀스뿐. 둘 다 타임스탬프가 없습니다.
   → 계획에 있던 "전체 타임스탬프 90% 지점으로 분할"은 못 합니다.

   대신 아이템 자체를 통째로 빼는 방식으로 만들었습니다.
     scripts/cold_split.py
     아이템 10%를 골라 학습·검증에서 완전히 제거하고,
     테스트에서는 그 아이템이 정답으로만 등장하게 합니다.

   검증 결과 (work/cold/beauty_strat10):
     학습·검증에 COLD 등장 0회
     테스트에서 COLD는 정답 위치에만 3,314건 (= 정답이 COLD인 유저 3,314명)

   ⚠️ 이건 "학습에서 못 본 아이템을 추천할 수 있는가"를 재는 것이지,
      "시간이 흐르며 새로 등장한 아이템"을 재는 게 아닙니다.
      논문에 쓸 때 이 구분을 명시해야 합니다.

3. 수치 비교 기준
   ❌ TIGER 원논문 NDCG@10 0.0374 와 비교하면 안 됩니다
   ✅ GRID 기준선 NDCG@10 0.0347 로 비교합니다
```

```

   저는 실제로 밟을 뻔했습니다 (다행히 타이밍이 어긋나 오염은 없었습니다).

거르는 방법 두 가지를 같이 쓰면 됩니다.
  ① 이번 실행을 시작한 시각 이후에 만들어진 파일만 본다
  ② .hydra/overrides.yaml 에 기대한 experiment= 가 적힌 실행만 본다

scripts/sweep_layers.py 의 newest() 에 그렇게 넣어 뒀습니다. 참고하세요.

가장 안전한 건 한 머신에서 GRID 실행을 하나만 돌리는 것입니다.
```
