# 01. 배경과 목표

## 1. 추천 시스템이 하는 일

영화 100만 개 중에서 **이 사람이 볼 만한 10개**를 고르는 것. 그게 전부입니다.

지금까지의 방식은 **"점수 매기기"** 였습니다.

```
100만 개에 전부 점수를 매긴다 → 높은 순으로 10개
```

너무 느려서 2단계로 나눴습니다.
```
1단계: 100만 개 → 대충 500개로 추림    (빠르고 대충)
2단계: 500개만 정밀하게 점수 매김        (느리지만 정확)
```

**2016년 유튜브 논문이 만든 방식이고, 지금도 대부분 이렇게 돌아갑니다.**

## 2. TIGER — "고르지 말고 써내라"

**비유**
- 기존: 도서관에서 100만 권을 다 뒤져서 고름
- TIGER: 사서가 청구기호를 **그냥 말함**

### 어떻게 가능한가

영화 번호가 `영화 #472913` 이면 못 씁니다. 아무 의미가 없으니까요.
그래서 **의미가 담긴 번호**를 붙입니다.

```
아이언맨       →  (액션, 히어로, 마블, 1번)
아이언맨 2     →  (액션, 히어로, 마블, 2번)
노팅힐         →  (로맨스, 코미디, 영국, 1번)
```

실제로는 `(12, 7, 3, 1)` 같은 숫자지만, **앞자리가 큰 분류, 뒤로 갈수록 세밀**합니다.

이제 모델이 하는 일:
```
입력:  이 사람이 본 것 → 아이언맨, 토르, 헐크
출력:  액션 → 히어로 → 마블 → 4번   (한 칸씩 차례로 생성)
```

**문장 쓰듯이 다음 영화의 번호를 씁니다.**

### TIGER를 만드는 2단계

```
[1단계] 아이템 텍스트(제목·가격·브랜드·카테고리)
          → Sentence-T5 임베딩 (768차원)
          → RQ-VAE로 3단계 압축
          → (c₁, c₂, c₃) + 충돌방지 c₄

[2단계] 유저 히스토리를 번호 시퀀스로 바꿔서
          → T5 인코더-디코더가 다음 번호를 생성
          → 파라미터 약 1,300만 (아주 작은 모델)
```

## 3. 🚨 문제 — 인기 아이템에만 쏠립니다

### 실측 증거

**CRAB 논문 (Walmart, 2026)**
```
SASRec 대비 인기 아이템 추천 빈도:   TIGER +7.2%
SASRec 대비 비인기 아이템 추천 빈도:  TIGER −4.1%
```

**Ghost 논문 (2026)**
```
LC-Rec이 실제로 추천한 것:
   인기 아이템 24,212개  vs  비인기 560개    (43 : 1)

인기/비인기 성능 격차:  최대 45배
```

### 왜 그런가 — Ghost가 규명한 두 원인

**① 그래디언트 기아**
```
인기 아이템 토큰  →  정답으로 자주 등장  →  계속 강화됨
비인기 토큰       →  "오답 후보"로만 등장 →  계속 밀려남

비인기 아이템은 "틀린 답"으로만 학습에 참여합니다.
```

**② 분기점에서의 기하급수적 억제**
```
번호를 한 칸씩 쓸 때, 인기와 비인기가 경쟁하는 갈림길이 생깁니다

갈림길 1개 통과 확률:  γ  (1보다 작음)
갈림길 z개면:          γ^z   ← 곱해집니다

→ 갈림길을 지날 때마다 비인기가 살아남을 확률이 기하급수적으로 줄어듭니다
```

## 5. 민찬 담당이 바뀐 이유

원래 배정은 **"디코딩 개입"** 이었습니다. *"답 뽑는 규칙을 바꿔서 비인기 아이템을 살리자"* 는 방향이었는데, 조사해보니 **이미 여러 팀이 하고 있었습니다.**

```
TIGER 원논문(2023) 4장   계층별 샘플링 + temperature 실험 이미 있음
BARGE / HPR (2026)      층별 재랭킹으로 디코딩 드리프트 억제
GRC (2026)              생성 → 반성 → 수정 3단계 디코딩
MindRec, LOHRec         계층 디코딩
```

**그래서 방향을 두 개로 바꿨습니다.**

### ① 구간별 평가 인프라 — 팀 공통 자산

```
세 갈래가 모두 "exploration이 좋아졌다"를 증명해야 하는데
지금 팀에 그걸 잴 자가 없습니다.

전체 평균 Recall만 보면?  →  비인기 아이템은 샘플이 적어 안 움직입니다

Ghost 사례:  비인기 노출이 17배 늘었는데
             전체 정확도는 오히려 7% 떨어졌습니다
             → 전체 평균으로는 성과가 안 보입니다
```

**HEAD / BODY / TAIL / COLD 구간별로 나눠서 재는 도구를 만듭니다.**

### ② 층 수 × 구간 — 연구 주제

세 논문이 서로 다르게 말합니다.

| 논문 | 주장 | 근거 |
|---|---|---|
| **TIGER** (2023) | "번호 길이를 바꿔도 robust하다" | 정량 수치 미제시 |
| **GRID** (2025) | "층을 늘리면 성능이 떨어진다" | 3층 0.0422 → 5층 0.0396 (**전체 평균**) |
| **VarLenRec** (2026) | "head는 짧게, tail은 길게가 최적" | **구간별** 측정 |
| **SA²CRQ** (2026) | "head는 길게, tail은 짧게" | ← VarLenRec과 **정반대** |

> **질문: GRID가 본 "층을 늘리면 나빠진다"는 전체 평균이다.**
> **구간별로 나누면 head는 나빠지고 tail은 좋아지는 걸 평균 낸 결과 아닌가?**

**그리고 Ghost가 실제로 head 5토큰 / tail 7토큰을 쓰고 Tail 성능 +63.91%를 냈습니다.**
→ VarLenRec 가설을 지지하는 실증 사례입니다.

## 6. 왜 GRID를 베이스로 쓰나

### TIGER는 공식 코드가 없습니다

Google DeepMind가 논문만 내고 코드를 공개하지 않았습니다.
비공식 구현이 5개 있는데 **성능이 최대 14% 차이납니다.**

| 구현 | Beauty Recall@10 | 원논문 대비 | NDCG@10 | 원논문 대비 |
|---|---|---|---|---|
| **원논문** (3시드 평균) | 0.0642 | — | 0.0374 | — |
| 🥇 **GRID** | **0.0639** | **−0.5%** | 0.0347 | −7.2% |
| XiaoLongtaoo | 0.0594 | −7.5% | 0.0321 | −14.2% |
| NonameUntitled | 0.0582 | −9.3% | ? | ? |
| EdoardoBotta (835⭐) | **미보고** | — | **미보고** | — |

**"어느 구현을 썼느냐"가 "무슨 방법을 썼느냐"보다 영향이 큽니다.**

### GRID의 장점

```
✅ 원논문 재현도 1위
✅ 5시드 평균 수치 공개  →  우리 재현이 맞는지 즉시 확인 가능
✅ 어블레이션 8종 완비   →  함정 회피
✅ 양자화 3종 교체 가능
✅ T5 기반이라 가벼움 (1,300만 파라미터)
✅ Snap Research 공식

⚠️ 비상업 연구 전용 라이선스 (랩 연구·논문은 허용)
⚠️ 열린 이슈 18개, 메인테이너 응답 없음
```

## 7. ⚠️ 팀이 꼭 알아야 할 것 4가지

### ① TIGER의 강점은 Recall이 아니라 NDCG입니다

```
Beauty  Recall@10  +0.15%   ← 거의 안 오름
        NDCG@10   +17.43%   ← 크게 오름
```

**"더 많이 맞히는" 게 아니라 "맞힌 걸 더 앞에 놓는" 모델입니다.**
우리 목표(안 뜨던 걸 뜨게 하기)는 Recall을 올려야 하는 일입니다.

### ② TIGER의 콜드스타트 강점은 만들어진 것입니다

논문의 콜드스타트 실험을 원문으로 확인했습니다.
```
ε = "신규 아이템을 최대 몇 % 끼워 넣을까" 라는 하이퍼파라미터를 두고
    후보 목록에 강제로 자리를 예약합니다

모델이 스스로 신규 아이템을 생성하는 게 아닙니다.
```

그리고 2026년 논문이 시간 기준 분할로 재실험하니 **신규 아이템 Recall이 거의 0**이었습니다.
```
Beauty 0.00000 / Sports 0.00004 / Toys 0.00000
```

### ③ DGU/MGU는 롱테일 도달을 재지 않습니다

```
DGU/MGU = "추천 분포가 과거 상호작용 분포와 얼마나 다른가"

그런데 과거 분포 자체가 옛 시스템의 결과물입니다
→ DGU = 0 은 "옛 편향을 충실히 재현"한다는 뜻

→ 롱테일 도달을 직접 재는 지표를 따로 둬야 합니다
```

### ④ 정확도와 exploration은 함께 올릴 수 있습니다

**이론** — [Reconciling the Accuracy-Diversity Trade-off](https://arxiv.org/abs/2307.15142) (WWW 2024, Kleinberg 등)
> 트레이드오프는 우리가 성공을 측정하는 방식의 산물이지, 본질적 충돌이 아니다.

**실증**
| 논문 | 정확도 | 다양성/공정성 |
|---|---|---|
| SPRINT | **+15.70%** | **+7.12%** |
| VarLenRec | head **+41.3%** | tail **+6.8%** |
| Spotify GLIDE | Recall@30 **+29.9%** | 낯선 콘텐츠 NDCG **+35.4%** |

**단, 조건이 있습니다.**
```
❌ 다양성을 억지로 주입 (temperature ↑)     →  트레이드오프
✅ 편향을 제거 (식별자·도달가능성 개선)      →  둘 다 상승
```
