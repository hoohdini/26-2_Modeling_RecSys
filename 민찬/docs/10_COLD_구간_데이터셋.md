> **한 줄 요약**

## 1. 문제 — COLD 가 33개뿐이었습니다

`docs/08` 에서 확인했듯이 지금 데이터는 leave-one-out 분할이라
학습에 한 번도 안 나오는 아이템이 **33개(0.3%)** 뿐입니다.
"신규 아이템 추천이 좋아졌다"를 이 33개로 재는 건 불가능합니다.

`HANDOFF.md` 3절의 3순위가 이걸 풀기 위한 **"시간 기준 분할"** 이었습니다.
전체 타임스탬프의 90% 지점을 잘라 뒤쪽에만 나오는 아이템을 신규로 삼는 방식입니다.

---

## 2. 🚨 그런데 시간 기준 분할은 이 데이터로 못 합니다

### 확인 ① TFRecord 에 타임스탬프 필드가 없습니다

네 split(`training`/`evaluation`/`testing`/`items`)의 필드를 전부 열어 봤습니다.

```
sequence_data  int64    아이템 id
user_id        int64
embedding      float    아이템 임베딩 (길이 = 시퀀스 길이 × 768)
text           bytes    아이템 제목
items/ 만 다름:  id, embedding, text
```

시간 정보가 **어디에도 없습니다.**

### 확인 ② 아이템 id 도 시간을 담고 있지 않습니다

"id가 등장 순서대로 매겨졌다면 id를 시간 대용으로 쓸 수 있지 않을까"를 확인했습니다.
시퀀스는 유저별로 시간순 정렬돼 있으므로, id가 시간을 담고 있다면
**시퀀스 위치와 아이템 id 가 같이 커져야** 합니다.

```
유저 5,120명 (길이 5 이상)
시퀀스 위치 vs 아이템 id  스피어만 상관   평균 +0.07   중앙값 +0.09
                          양의 상관인 유저 비율        54.6%
```

> 시간을 담고 있다면 상관 +1.0, 양의 비율 100% 에 가까워야 합니다.
> **54.6% 는 동전 던지기와 같습니다.** 아이템 id 는 시간과 무관합니다.

### 결론

```
시간 기준 분할을 하려면 원본 Amazon 리뷰(unixReviewTime)를 다시 받아
ASIN 으로 이어 붙여야 합니다.  → 별도 다운로드가 필요합니다 (아직 안 함)
```

⚠️ 원본 리뷰 데이터를 받을지는 **민찬님이 정하실 일**이라 진행하지 않았습니다.
받는다면 P5 전처리 스크립트와 같은 ASIN 매핑을 확보해야 합니다.

## 3. 대안 — 아이템 홀드아웃

타임스탬프 없이도 되는 방식입니다. 콜드스타트 논문에서 널리 씁니다.

```
① COLD 후보 = 테스트 정답으로 한 번 이상 등장하는 아이템
   (정답으로 안 나오면 홀드아웃해도 평가할 수 없습니다)
② 그중 카탈로그의 10% 를 뽑는다
③ training / evaluation 시퀀스에서 그 아이템을 전부 지운다  ← "신규"의 정의
④ testing 은 정답(마지막)만 남기고 앞 이력에서만 지운다
⑤ 너무 짧아진 시퀀스는 버린다
⑥ items/ (카탈로그)는 건드리지 않는다   ← 가장 중요
```

**⑥ 이 왜 중요한가.** TIGER 는 아이템 **임베딩**만 있으면 학습에서 한 번도 못 본
아이템에도 SID를 붙일 수 있습니다. 바로 그 능력이 TIGER 가 주장하는 콜드스타트 강점입니다.
카탈로그에서 빼 버리면 재려던 것을 없애는 셈이 됩니다.

### 시간 분할과 뭐가 다른가 (반드시 밝혀야 할 것)

```
시간 분할        신규 아이템 효과 + 그 시점의 유저 취향 변화가 섞임
아이템 홀드아웃   신규 아이템 효과만 분리됨  ← 교란이 오히려 적습니다
```

논문에 쓸 때는 "temporal split" 이 아니라 **"item hold-out cold-start simulation"** 이라고
정확히 써야 합니다. 둘을 같은 것처럼 쓰면 안 됩니다.

## 4. 만든 것 — 두 가지 판

`scripts/cold_split.py` 로 만들었습니다. 둘 다 카탈로그의 10%(1,210개)를 COLD 로 뺐습니다.

| | **beauty_strat10** | **beauty_tail10** |
|---|---|---|
| 표본 방식 | 인기 구간 비율 유지 | 비인기(TAIL)에서만 |
| COLD 아이템 | 1,210 (10.0%) | 1,210 (10.0%) |
| 구간별 내역 | HEAD 242 / BODY 726 / TAIL 242 | TAIL 1,210 |
| **COLD 정답 유저** | **3,314명 (14.8%)** | **2,788명 (12.5%)** |
| 🚨 학습 상호작용 손실 | **17,254건 (11.2%)** | **3,276건 (2.1%)** |
| 학습 유저 | 22,363 → 19,941 | 22,363 → 21,806 |

### 어느 쪽을 쓸 것인가

```
beauty_tail10   기본으로 권합니다.
                학습 데이터를 2.1%만 건드리므로 원본과 비교가 깨끗합니다.
                현실의 신규 아이템도 대개 비인기에서 시작합니다.

beauty_strat10  "신규 아이템 일반"을 대표합니다.
                🚨 학습 상호작용이 11.2% 줄어듭니다. 성능이 떨어졌을 때
                   COLD 때문인지 학습 데이터가 줄어서인지 구분이 안 됩니다.
                   쓴다면 원본 대비 대조군이 반드시 필요합니다.
```

### 만든 뒤의 구간 분포

```
beauty_tail10
구간        아이템수   아이템비율   상호작용    점유율    등장횟수
HEAD        2,177     18.0%     88,704    59.4%    16~367
BODY        6,529     54.0%     52,424    35.1%      5~16
TAIL        2,177     18.0%      8,278     5.5%       1~5
COLD        1,210     10.0%          0     0.0%       0~0   ← 학습에 0건
UNSEEN          8      0.1%          0     0.0%       0~0
```

`COLD` 와 `UNSEEN` 은 **절대 합치지 않습니다.**
COLD 는 일부러 뺀 것, UNSEEN 은 우연히 안 나온 것(8개)입니다.
합치면 신규 아이템 성능이 8개짜리 잡음에 오염됩니다.

## 5. 검증 — 세 겹으로 확인했습니다

### ① 자르는 로직 — `tests/test_cold_split.py` (합성 데이터, 15개 통과)

가장 무서운 버그는 **조용한 어긋남**입니다.
아이템 id 만 지우고 임베딩을 안 지우면 3번 자리에 4번 임베딩이 들어갑니다.
에러도 안 나고 학습도 되지만 결과가 통째로 틀립니다.

그래서 아이템마다 값을 알아볼 수 있는 임베딩(`[i, i+0.1, i+0.2, i+0.3]`)을 만들어 두고,
자른 뒤에도 **모든 자리에서 아이템과 임베딩·제목이 계속 짝이 맞는지** 확인합니다.

```
OK   학습에 COLD 가 남아 있지 않다
OK   유저0의 정답 4(COLD)가 살아 있다
OK   유저0 이력에서 2가 지워졌다
OK   임베딩·텍스트가 아이템과 계속 짝이 맞는다      ← 핵심
OK   손대지 않은 레코드의 임베딩도 정확하다
OK   verify 가 오염을 잡아낸다                     ← 일부러 오염시켜 확인
```

### ② 만들어진 데이터셋 — `cold_split.py` 가 다시 읽어 확인

```
✅ 학습/검증에 COLD 0건 · 테스트 정답이 COLD 인 유저 3,314명 (14.8%)
```

### ③ GRID 가 읽을 수 있는가 — `tests/test_cold_dataset_loads.py`

GRID 의 파싱 절차(첫 레코드로 스키마 추론 → `tf.io.parse_example`)를 그대로 재현해
실제 데이터셋을 끝까지 읽습니다.

⚠️ **TIGER 학습을 직접 돌려 본 것은 아닙니다.** 스키마와 필드 길이까지만 확인했습니다.
   GPU 확보 후 실제 학습으로 최종 확인이 필요합니다. 명령은 아래 7절에 있습니다.

## 7. 다시 만드는 법 / 다음 단계

```bash
# 1. COLD 데이터셋 만들기 (약 4분)
python scripts/cold_split.py \
  --data-dir data/amazon_data/beauty \
  --out-dir  work/cold/beauty_tail10 \
  --cold-fraction 0.10 --strategy tail --seed 42

# 2. 구간 정의 (COLD 표시가 붙습니다)
python scripts/item_segments.py \
  --data-dir work/cold/beauty_tail10 \
  --cold-items work/cold/beauty_tail10/cold_items.json \
  --out work/segments/beauty_tail10.json

# 3. 검증
python tests/test_cold_split.py
python tests/test_cold_dataset_loads.py

# 4. ⬜ TIGER 학습 — 랩 GPU 필요. 아직 안 돌려 봤습니다
#    num_hierarchies 는 코드북 층 수 + 1 입니다
scripts/grid_mac.sh train experiment=tiger_train_flat \
  "data_dir='$PWD/work/cold/beauty_tail10'" \
  "semantic_id_path='<Step 4 출력>'" num_hierarchies=4

# 5. ⬜ 구간별 평가 — COLD 행이 자동으로 나옵니다
python scripts/segment_eval.py \
  --sid-map <Step4> --predictions <Step6> \
  --segments work/segments/beauty_tail10.json \
  --data-dir work/cold/beauty_tail10 \
  --out work/eval/cold_tail10.json
```

### 이 데이터셋으로 답할 수 있게 되는 질문

```
· TIGER 가 정말 학습에 없던 아이템을 추천하는가 (COLD 행의 HR@10 이 0이 아닌가)
· 층 수(L)를 바꾸면 COLD 가 HEAD/TAIL 과 다르게 반응하는가   ← 우리 연구 주제
· Ghost 가 보고한 "비인기 노출 43:1 → 1.6:1" 이 COLD 에서도 재현되는가
  (segment_eval.py 가 HEAD:TAIL 노출비를 자동으로 냅니다)
```

⚠️ COLD 는 학습에 0건이므로 **인기도 기반 추천은 구조적으로 못 맞힙니다.**
COLD HR 이 0에 가깝게 나와도 그 자체가 버그는 아닙니다.
비교 대상은 "다른 L / 다른 방법에서의 COLD HR" 이지 HEAD 가 아닙니다.
