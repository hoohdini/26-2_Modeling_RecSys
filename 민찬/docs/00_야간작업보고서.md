
## 3. 🎯 Ghost 논문 핵심 주장 — 데이터로 100% 검증

### SID 구조를 직접 확인했습니다

```
head 아이템:  ['<a_143>', '<b_213>', '<c_203>', '<d_242>', '<p_1>']
                └──────────── 의미 4단계 ────────────┘  └충돌방지┘
                                                            5 토큰

tail 아이템:  ['<a_30>', '<b_170>', '<c_159>', '<d_30>', '<e_143>', '<f_232>', '<p_1>']
                └──────── head와 같은 4단계 ────────┘  └─ 추가 2단계 ─┘  └충돌방지┘
                                                                          7 토큰
```

**논문의 `L^h = 4`, `L^t = 2` 입니다.**

### 핵심 검증: 접두사 상속

> Ghost 논문 주장: *"tail 아이템은 의미적으로 가장 가까운 head 아이템의 앞 토큰들을 물려받는다"*

**Instruments 데이터 검증 결과**
```
head 고유 접두사(a,b,c,d):  1,820개  (head 아이템 1,847개 중)

tail 8,075개의 앞 4토큰이 head 접두사와 일치하는가?
   일치:    8,075개  (100.0%)   ✅
   불일치:      0개  (  0.0%)

접두사 하나당 tail: 평균 5.3개, 최대 54개
```

**전부 일치합니다. 논문 주장이 데이터로 완벽히 확인됐습니다.**

### 3개 데이터셋 모두 동일 구조

| 데이터셋 | 전체 | head | tail | head비율 | head길이 | tail길이 | 접두사일치 |
|---|---|---|---|---|---|---|---|
| Instruments | 9,922 | 1,847 | 8,075 | 18.6% | 5 | 7 | **100.0%** |
| Arts | 20,956 | 4,035 | 16,921 | 19.3% | 5 | 7 | **100.0%** |
| Games | 16,859 | 3,242 | 13,617 | 19.2% | 5 | 7 | **100.0%** |

### 🎯 여기서 나온 두 가지 부수적 발견

**① 구간 정의 걱정이 해소됐습니다**

제가 앞서 *"Ghost는 누적 80% 기준, VarLenRec은 개수 상위 20% 기준이라 비교가 안 된다"* 고 우려했는데,

```
Ghost 실제 head 비율:  18.6% / 19.3% / 19.2%
VarLenRec 기준:        20%

→ 사실상 같습니다. 비교 가능합니다.
```

**② Ghost는 VarLenRec 편입니다 — SA²CRQ와 반대**

```
Ghost:      head 5토큰(짧게)  /  tail 7토큰(길게)
VarLenRec:  head 짧게         /  tail 길게        ← 일치 ✅
SA²CRQ:     head 길게         /  tail 짧게        ← 반대 ❌
```

**SA²CRQ vs VarLenRec 모순에서 Ghost는 VarLenRec 쪽에 섰습니다.**
그리고 실제로 Tail HR@10 **+63.91%** 를 냈습니다. 이건 VarLenRec 가설을 지지하는 실증입니다.

## 4. ⚠️ Ghost 데이터에서 P5 순차 ID 패턴 확인

`Instruments.inter.json` 을 열어봤습니다.

```
유저 0:  [0, 1, 2, ..., 18]     ← 완전 연속
유저 1:  [19, 20, ..., 34]      ← 완전 연속
유저 2:  [35, ..., 40]          ← 완전 연속
```

**TIGER 논문 부록 D가 지적한 그 패턴입니다.**
> P5는 아이템 ID를 순차 재매핑하고 이걸 분할 전에 적용한다. 그래서 `a, a+1, a+2...` 형태의 시퀀스가 많이 생긴다.

### 영향은 없을 것으로 판단합니다

```
누수 메커니즘:  아이템 ID 문자열 → SentencePiece → 서브워드 공유 → 누수
                                    ↑ 여기가 핵심

Ghost/TIGER:    아이템 ID를 문자열로 모델에 넣지 않음
                대신 Semantic ID (<a_143>, <b_213>, ...) 사용
                → 서브워드 공유가 일어날 수 없음
```

**다만 Ghost가 P5 전처리를 그대로 썼다는 증거이므로 기록해둡니다.**

### 데이터 규모 (Instruments)
```
유저:        24,772명
아이템:       9,922개
시퀀스 길이:  평균 8.32 / 중앙값 6 / 최소 5 / 최대 218
```
TIGER 논문의 Sports(평균 8.32)와 정확히 같은 수치입니다.

## 4.5. 🎯 Ghost 코드 정밀 분석 (로컬에서 직접 읽음)

### ① 슬라이딩 윈도우 증강이 Ghost에는 코드로 있습니다

`data.py` → `_process_train_data()`
```python
token_items = self.remapped_inters[uid][:-2]      # 마지막 2개 제외
for i in range(1, len(token_items)):              # ← 슬라이딩 윈도우
    one_data["item"]   = token_items[i]           #   정답 = i번째
    history_tokens     = token_items[:i]          #   입력 = 0 ~ i-1
    history_tokens     = history_tokens[-self.max_his_len:]
```

**유저 시퀀스 `[a,b,c,d,e]` 하나가 여러 학습 예시로 펼쳐집니다.**
```
[a]     → b
[a,b]   → c
```

> **GRID와의 차이**: GRID는 이 로직이 코드에 없고 데이터에 내장돼 있습니다.
> Ghost는 코드에서 처리합니다. → **Ghost가 커스텀 데이터를 쓰기 더 쉽습니다.**

### ② 분할은 표준 leave-one-out 확인 ✅

```python
학습:   inters[uid][:-2]   +  슬라이딩 윈도우
검증:   items[-2]          (뒤에서 두 번째)
테스트: items[-1]          (마지막)
```
TIGER, GRID와 동일합니다.

### ③ AUO의 negative 선택 — 논문보다 정교합니다

논문은 *"tail 아이템마다 유사한 head를 억제"* 라고만 썼는데, **코드는 양방향입니다.**

```python
# Head → Tail : 정답이 head면, 비슷한 tail을 억제
# Tail → Head : 정답이 tail이면, 비슷한 head를 억제
```

**선택 알고리즘**
```python
candidate_pool_size = 50

1. 임베딩 정규화 후 내적으로 유사도 계산
2. 상위 50개 후보 추출                    ← "내용이 비슷한 것들"
3. 각 후보의 SID 접두사 일치 길이 계산
      match_len: 앞에서부터 몇 개 토큰이 같은가
4. sort(오름차순) 후 앞에서 negative_k개   ← "번호는 가장 다른 것들"
```

**= "내용은 비슷한데 번호는 완전히 다른" 아이템을 억제합니다.**

### ④ 🎯 SKT와 AUO가 맞물려 작동합니다 — 논문에 없는 발견

앞서 검증했듯 **tail의 앞 4토큰은 100% 어떤 head의 접두사입니다.**

```
정답이 tail 아이템 T 라고 하면
   T의 앞 4토큰 = 어떤 head H의 앞 4토큰   (SKT 구조상 반드시)
        ↓
   H를 negative 후보로 평가하면 match_len = 4  (최댓값)
        ↓
   오름차순 정렬에서 맨 뒤로 밀림
        ↓
   ★ "자기 부모 head"는 negative로 선택되지 않습니다
```

**즉 억제 대상은 "다른 가지에 있는, 내용만 비슷한 head"입니다.**
자기가 물려받은 부모는 건드리지 않습니다. **SKT가 AUO의 안전장치 역할을 합니다.**

이건 논문에 서술되지 않은 구조입니다. 코드를 읽어야만 보입니다.

### ⑤ `evaluate.py` — 구간별 집계 없음 확인 ✅

전문(2KB)을 읽었습니다.

```python
hit_k    →  상위 k개에 하나라도 맞으면 +1     (= Recall@K, 정답 1개니까)
ndcg_k   →  res[i] / log2(i+2)               (표준 NDCG)

무효 ID  →  if seq not in all_items: scores[i] = -1000
             (제거가 아니라 맨 뒤로 "강등")
```

**head/tail 파일이 데이터에 있는데도 `evaluate.py`는 쓰지 않습니다.**
→ 논문의 `43:1 → 1.6:1` 분석은 별도 스크립트로 한 것이 확실합니다.
→ **우리가 구간별 집계를 붙일 자리가 여기입니다.** (약 40줄 추가면 될 것으로 보임)

## 9. 제 판단 — 아침에 논의하실 것

### GRID vs Ghost, 이 맥 기준으로 다시 보면

| | **GRID** | **Ghost** |
|---|---|---|
| 모델 크기 | 1,300만 | **30억 (Qwen2.5-3B)** |
| 요구 환경 | CPU/MPS 가능해 보임 | torchrun 2 GPU + DeepSpeed |
| **이 맥(24GB)에서** | 🟢 **충분** | 🔴 **어려울 것** |
| 데이터 | 별도 다운로드 (zip 오류 보고 있음) | 🟢 저장소에 포함 |
| 구간 실험 재료 | 없음 | 🟢 head/tail 완비 |

**→ 이 맥에서 직접 돌린다면 GRID가 사실상 유일한 선택입니다.**

**→ 다만 랩에 NVIDIA GPU 서버가 있다면 Ghost도 가능합니다.** 그러면 선택지가 늘어납니다.
**아침에 랩 GPU 자원부터 확인해주세요.** 이게 Plan A/B를 가릅니다.
