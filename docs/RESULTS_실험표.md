### LOO 와 정반대입니다 — 정확도

LOO 에서 CRAB 은 정확도를 **깎았습니다**(N@10 텍스트 −0.0023 · G 튜닝식 −0.0033, 둘 다
바닥 초과). Temporal W5 에서는 세 조건 모두 **미세하게 올랐습니다**(+0.0003).
전부 바닥(0.0016) 한참 아래라, 말할 수 있는 것은
**"Temporal 에서는 CRAB 이 정확도를 깎지 않는다"** 까지입니다.

### 다양성은 주소에 따라 갈립니다 — 겹치면 상쇄됩니다

**텍스트 주소에서만 CRAB 이 크게 먹혔습니다.**

```
APLT@10   0.0199 → 0.0362  (+0.0163, 바닥 0.0176 에 근접하나 미달)
커버리지   0.1307 → 0.2498  (거의 2배)
Gini      0.9725 → 0.9479  (편중 완화)
```

**반면 그래프 주소에 얹으면 다양성이 나빠집니다.**

```
G 튜닝식  APLT 0.0416 → 0.0305   Gini 0.9526 → 0.9562
G 고전    APLT 0.0497 → 0.0324   Gini 0.9213 → 0.9599   Cov 0.3232 → 0.1766
```

그래프 증강과 CRAB 은 **둘 다 인기 쏠림을 푸는 처방**입니다 — 그래프는 관계로 모으고,
CRAB 은 빈도로 흩뜨립니다. 이미 그래프로 분산된 주소 위에 CRAB 을 또 얹으면 **과교정**이
일어나는 것으로 보입니다. `results/crab.json` 의 사전 진단에서
`edge_hh_vs_random = 4.26`(그래프 간선이 head-head 에 무작위 대비 4.26배 편중)이 나왔던
것과 연결될 가능성이 있습니다. 팀브리핑이 미리 제기한 *"CRAB vs G-SID 충돌 — 두 처방이
반대로 미는가"* 가 여기서 실제로 관측된 셈입니다.

> ⚠️ **위 차이는 전부 노이즈 바닥 근처이거나 그 아래입니다.** "CRAB 은 텍스트 주소에서만
> 쓸모 있고 그래프 주소와는 궁합이 나쁘다" 는 **현재 데이터가 가리키는 방향일 뿐,
> 시드 1회로는 주장할 수 없습니다.** W4 와 MaskGR 쪽이 나오면 방향 일관성을 볼 수 있습니다.

**W4 · MaskGR × CRAB Temporal 은 아직 측정 중입니다.**

## 🎤 발표 방향 — 확정 제안

> **주 기여는 G-SID(그래프 증강)로 갑니다.** 정확도와 다양성을 **동시에** 올린 유일한
> 처방이고, 세 트랙에서 모두 노이즈 바닥을 넘습니다.

| 주장 | 근거 | 방어력 |
|---|---|---|
| 그래프 증강 > 텍스트 주소 | LOO +0.0040 · W4 +0.0023 · W5 +0.0021 | **세 트랙 모두 바닥 초과** |
| 콜드 아이템에서 특히 | COLD@50 0.0429 → 0.0620 (+45%) | 큰 폭 |
| Temporal 에서 EASE_R 을 넘으려면 그래프가 필요 | 텍스트 0.0068 < EASE_R 0.0071 < 그래프 0.0090 | 명확한 스토리 |
| 다양성도 동시에 개선 | APLT 0.0199 → 0.0497 (W5, 고전) | 바닥 초과 |

### 스토리 5단계

1. **문제** — TIGER 는 EASE_R 보다 정확한데 롱테일 노출은 오히려 더 나쁘다 (실측)
2. **처방** — 모델이 아니라 **주소(SID)** 를 바꿔 푼다: 그래프 증강
3. **결과** — 정확도 · 콜드 · 다양성 **동시 개선**, LOO · W4 · W5 세 트랙에서 재현
4. **대조** — 같은 문제에 CRAB(빈도 분산)과 확산 다이얼도 시도했으나,
   **CRAB 은 정확도만 깎았고 다이얼은 다양성을 못 샀다**
5. **한계** — 시드 1회. 우리 튜닝식 vs 고전 블렌딩은 아직 구분 못 함

> 💡 **4번(실패한 시도)을 반드시 넣으십시오.** "왜 하필 그래프인가" 가 대조로 증명됩니다.
> 실패한 처방 두 개를 같은 조건에서 재 본 것이 오히려 주 기여를 강하게 만듭니다.

### 보조로 쓸 수 있는 관찰

**트랙에 따라 승자가 뒤집힙니다** — LOO 에서는 TIGER 가 압도(N@10 0.0384 vs 0.0239)하는데
Temporal 에서는 MaskGR 이 6/6 앞섭니다. 흥미롭지만 개별 차이가 대부분 바닥 아래라
**주 주장으로 쓰지 말고 관찰로만** 넣으십시오.

| **그래프 증강 > 텍스트 주소** | LOO 튜닝식 / LOO 고전 / W4 튜닝식 / W5 튜닝식 | +0.0021 ~ +0.0040 |
| **Temporal 에서 TIGER 텍스트는 EASE_R 을 못 이긴다** | W5 N@10 0.0068 < 0.0071 | — |
| **그래프를 넣으면 EASE_R 을 넘는다** | W5 튜닝식 0.0090 · 고전 0.0084 | +0.0013 ~ +0.0019 |
| **CRAB 은 정확도를 깎는다** | 텍스트 −0.0023 · G 튜닝식 −0.0033 | 바닥 초과 |
| **MaskGR 은 롱테일 노출이 나쁘다** | 전 조건 APLT 가 TIGER 의 1/2~1/4 | 대부분 바닥 초과 |

### ❌ 주장할 수 없는 것 (시드 1회로는)

| 주장하고 싶은 것 | 실제 차이 | 바닥 |
|---|---|---|
| 우리 튜닝식 > 고전 블렌딩 | LOO +0.0010 · W4 +0.0008 · W5 +0.0006 | 0.0016 |
| CRAB 이 롱테일 노출을 늘린다 | +0.0011 ~ +0.0066 | 0.0176 |
| Temporal 에서 MaskGR > TIGER | 4/6 이 +0.0007~+0.0015 | 0.0016 |

> **방향의 일관성은 별개 정보입니다.** 튜닝식은 3개 트랙에서 3/3 고전보다 높고,
> Temporal 에서 MaskGR 은 6/6 TIGER 보다 높습니다. 개별 차이가 바닥 아래여도
> 이 일관성 자체는 우연으로 보기 어렵습니다. **다만 그것을 수치로 주장하려면
> 시드 2회가 필요합니다.**

## 이번 측정에서 드러난 문제 — 문서 정정

### 1. MaskGR 덤프는 변환 없이 못 읽습니다 (`docs/HANDOFF_MaskGR.md` 정정)

기존 문서:

> 그래서 **트랙 C 하네스(`tiger_to_eval.py` 이하)가 수정 없이 MaskGR 덤프를 읽습니다.**

**사실이 아닙니다.** 두 덤프는 껍데기(키·shape)가 같지만 **코드 값의 좌표계가 다릅니다.**

```
TIGER   semantic_ids 범위 [0, 255]      계층별 원본 코드
MaskGR  semantic_ids 범위 [0, 1284]     계층 오프셋이 더해진 값 (h * 257 + c)
```

MaskGR 은 계층마다 코드 256 개 + **마스크 토큰 1 개 = 257 칸**을 씁니다
(`discrete_diffusion_module.py:73` `num_embeddings_per_hierarchy = vocab_size + 1`).
변환 없이 넣으면 **invalid_sid_rate = 1.0, 전 지표 0** 이 나옵니다.

검증: 오프셋 `arange(H)*257` 을 빼면 전 값이 `[0,255]` 에 들어가고,
**공통 유저 7,264명 전원의 `label_sid` 가 TIGER 덤프와 정확히 일치**합니다.
stride 256 · 258 은 각각 489/500, 500/500 이 범위를 벗어나 반증됩니다.

→ `code/maskgr_to_tiger.py` 를 추가했습니다. `tiger_to_eval.py` 에 자동 감지를
넣지 않은 이유는 **CRAB 주소가 정상적으로 305 까지 가기 때문**입니다. "255 를 넘으면
오프셋" 규칙은 CRAB 을 오인해 망가뜨립니다.

### 2. MaskGR 은 어휘 크기를 SID 에서 유도하지 않습니다

TIGER 는 `codebooks.max()+1` 로 SID 텐서에서 유도하는데(`tiger_generation_model.py:497`),
MaskGR 은 `configs/model/experimental/discrete_diffusion_train.yaml` 의
`vocab_size: 256` 을 그대로 씁니다. CRAB 주소를 그냥 넣으면

```python
assert masked_input.max() < self.num_embeddings_per_hierarchy   # 305 < 257 → 실패
```

에서 죽습니다. `maskgr_train.sh` · `maskgr_eval_dump.sh` 에 `WIDTH` 인자를 추가해
`model.vocab_size` 로 넘기게 했습니다(기본값 256 이라 기존 호출은 그대로 동작).

### 3. `crab/README.md` — `M=3` 이 실제로는 2분할입니다

`crab_split_history.json` 을 보면 분할 75건(25토큰 × 3레벨) **전부** 자식 셋 중 하나가
비어 있습니다(`"257": 0.0`). 그래서 토큰 수는 256→281(+25)인데 코드 번호는 305 까지
나가 **레벨당 25개가 죽은 번호**입니다. 기존에 커밋된 `crab_baseline` ·
`crab_gsid_a01` · `crab_gsid_a03` 도 동일합니다.

### 4. `work/minchan/pick_winner.py` — 경로 버그로 후보 7개가 "붕괴" 오판

`pick_result.txt` 에서 11개 후보 중 7개가 `탈락: 붕괴` 로 기록됐는데, 같은 파일 위쪽에
`SID 읽기 실패 .../sid_out/sid_gstar_centered/...: No such file or directory` 가 있습니다.
실제 디렉토리는 `gsid_gstar_centered` 입니다. 파일을 못 열어 비트값이 `nan` 이 되고,
`nan >= 4.0` 이 거짓이라 붕괴로 처리됐습니다. 직접 열어보면 `gsid_gstar_centered` 는
최저 7.19 bit / 충돌 2.63% 로 건강합니다. **승자 2개는 바뀌지 않지만, "붕괴했다"는
기록은 사실이 아닙니다.**

### 5. 그 밖에 실행 중 겪은 함정 (README 함정 목록에 6·7·8번으로 추가됨)

- MaskGR 은 이미 정의된 키라 `+trainer.…` 가 아니라 `++trainer.…` 를 써야 합니다.
- `limit_val_batches` 에 분수를 못 씁니다(`IterableDataset` → `1.0` 이거나 정수).
- MaskGR 체크포인트 파일명 템플릿의 `val/recall@5` 안에 있는 `/` 가 디렉토리
  구분자가 되어 `checkpoints/*.ckpt` 로는 절대 안 잡힙니다. `set -e` 와 겹치면
  가드에 닿기도 전에 종료 코드 2 로 죽고 로그도 안 남습니다.
