02

파레토 곡선 — AR 모델에 다이얼을 달다

파레토 곡선은 "정확도를 조금 포기하면 다양성을 얼마나 얻는가"의 지도입니다. 곡선을 그리려면 조절 손잡이가 필요한데, TIGER는 빔서치라 손잡이가 없습니다. 점 하나만 찍힙니다.

그래서 GPU를 한 번만 쓰고, 생성된 후보 200개와 그 확률을 인기도 페널티로 다시 정렬했습니다. λ=0이면 원래 빔서치 순서 그대로이고, λ를 키우면 인기 상품이 아래로 밀립니다.

점수(i) = log p(i) − λ · log(1 + 학습등장횟수(i))

정확도 × 롱테일 노출 (오른쪽 위가 좋음)

파란 곡선은 λ를 0에서 12까지 돌린 TIGER. 점 위에 마우스를 올리면 값이 나옵니다.

읽을 점 넷

  1. EASE_R이 프론티어에서 밀려납니다. λ=0.2 / 0.5 / 1 세 지점이 EASE_R을 정확도·다양성 두 축 모두에서 이깁니다. 그리고 그걸 이기는 데 TIGER 재학습이 필요 없었습니다 — 디코딩 후 재정렬뿐입니다.
  2. 초반이 아주 쌉니다. λ=0.2에서 정확도를 2.6%만 내주고 롱테일 노출이 67% 오릅니다.
  3. ItemKNN은 살아남습니다. λ=2에서 노출은 ItemKNN을 넘지만(0.6842 vs 0.5952) 그 지점의 정확도는 낮습니다(0.0198 vs 0.0221). 이 곡선은 ItemKNN을 지배하지 못합니다. 다만 같은 지점에서 콜드 Recall@50은 0.0814로 ItemKNN(0.0702)보다 높습니다.
  4. Coverage는 λ=1에서 정점을 찍고 다시 내려갑니다. 페널티를 극단으로 밀면 모든 유저에게 같은 희귀 상품을 밀게 되기 때문입니다. 다양성 지표를 하나만 보면 안 되는 이유입니다.
발표에서 과장하면 안 되는 것 이건 재정렬 다이얼이지 생성 다이얼이 아닙니다. 후보 풀 밖의 상품은 λ를 아무리 키워도 추천될 수 없습니다. MaskGR의 확산 다이얼과 같은 종류의 기여로 주장하면 안 됩니다. TIGER 곡선은 "AR 모델에서 재정렬만으로 여기까지는 간다"는 참조선으로 쓰는 것이 정직하고, 그래야 MaskGR 곡선의 기여를 "다이얼이면 뭐든 좋다"와 구별해 주장할 수 있습니다.

참고로 후보 풀이 50개일 때는 곡선이 노출 0.38에서 천장을 쳤습니다. 200개로 넓히니 0.92까지 갔습니다 — 천장은 모델의 한계가 아니라 후보 풀의 한계였습니다. 넓히는 비용은 사실상 0입니다(Recall@10 0.06922 → 0.06927).

다이얼을 하나 더 — Coverage 문제의 해법

위 4번 관찰(페널티를 극단으로 밀면 Coverage가 내려간다)은 전역 페널티의 구조적 약점입니다. 그래서 유저를 순서대로 처리하면서 이번 라운드에 이미 추천된 횟수를 세고 그만큼 깎는 다이얼을 추가했습니다.

점수(i) = log p(i) − μ · log(1 + 이번_라운드_노출횟수(i))

두 다이얼은 서로 다른 다양성을 삽니다. 같은 정확도(NDCG@10 ≈ 0.035)에서:

다이얼NDCG@10APLT@10Coverage@10Gini@10
인기도 페널티 λ=0.50.03470.17060.50580.8428
노출 인지 μ=0.50.03530.13770.73910.7489
  • 인기도 페널티는 "비인기 상품에 슬롯을 더 준다"를 삽니다 → tail_exposure가 큽니다.
  • 노출 인지는 "노출을 고르게 편다"를 삽니다 → coverage와 gini가 압도적입니다. μ=8에서 Gini 0.3835로 ItemKNN(0.5337)보다도 고르게 퍼집니다.

파레토 축을 tail_exposure로만 잡으면 인기도 페널티가 항상 이깁니다. 그래서 07절 프로토콜에서 coverage를 반드시 병기하라고 한 것입니다.

노출 인지 모드의 성질 유저 처리 순서에 결과가 의존하는 온라인 알고리즘입니다. "유저별로 독립인 추천"이라는 가정이 깨집니다. 순서를 user_id 오름차순으로 고정해 재현성은 확보했지만, 발표에서는 이 성질을 반드시 밝혀야 합니다.
03

도달가능성 — 재정렬로는 절대 넘을 수 없는 벽

Coverage는 재정렬로 끌어올릴 수 있는 양입니다. 하지만 생성 후보 전체의 합집합은 재정렬이 절대 넘을 수 없습니다. 그게 도달가능성이고, 이 프로젝트가 나눈 세 축 중 첫 번째입니다.

TIGER가 후보에 올리는 상품은 카탈로그의 몇 %인가 (clip_L4)

학습 등장 횟수 버킷별 · 후보 깊이 top-10 / 50 / 200. zero-shot = 학습에 한 번도 안 나온 상품 43개.

top-10 top-50 top-200

학습에 없던 상품은 구조적으로 추천되지 않습니다

zero-shot 상품 43개는 후보를 200개까지 파고들어도 도달률 0%입니다. 체크포인트를 바꿔도 똑같습니다 — clip_L4 / seed7 / fullval 셋 다 0%, 60,000스텝 모델만 2%(43개 중 1개)입니다. 디코더가 학습에서 한 번도 타깃으로 본 적 없는 SID 열을 사실상 생성하지 않기 때문입니다.

재정렬 다이얼의 진짜 한계 후보 풀의 천장은 풀을 넓혀 올릴 수 있었습니다(50개 → 200개). 하지만 zero-shot 벽은 생성 분포 자체를 바꿔야 넘습니다. ④번 칸(MaskGR)의 확산 다이얼이 노려야 할 지점이 정확히 여기입니다.

편향은 재정렬이 아니라 생성 단계에서 이미 결정됩니다

clip_L4 기준, 후보 등장 횟수의 절반을 상위 920개(7.6%) 상품이 가져갑니다. top-200 안에 단 한 번도 안 뜨는 상품이 1,908개(15.8%)이고, 그중 zero-shot은 43/43(100%), few-shot은 311/726(42.8%)입니다.

노출 인지 다이얼은 도달가능한 것을 거의 다 씁니다 clip_L4의 top-200 도달률은 84.23%(10,193개)이고, 노출 인지 다이얼 μ≥4의 Coverage@10은 0.8415~0.8418(10,183~10,187개)에서 멈춥니다. 재정렬로 닿을 수 있는 상품의 99.9%를 이미 다 꺼내 쓰고 있습니다. 컷오프를 절반(@20→@10)으로 줄여도 이 값이 거의 안 움직인다는 점이 오히려 논지를 강하게 합니다 — 슬롯을 늘려서 닿는 게 아니라, 닿을 수 있는 게 거기까지입니다. Coverage를 더 올리려면 재정렬이 아니라 생성을 바꿔야 합니다.
04

곡선 차이가 유의한가 — 노이즈 바닥 재기

곡선 하나만 그리면 두 곡선의 간격이 진짜 차이인지 학습 노이즈인지 알 수 없습니다. 같은 레시피에 시드만 다른 두 실행의 간격이 노이즈 바닥입니다.

"유의하다"와 "노이즈보다 크다"는 다른 질문입니다 paired bootstrap은 이 두 모델이 이 유저들 위에서 정말 다른가를 잽니다. 그런데 seed7도 λ=0에서 "유의"하게 나옵니다 — 시드만 바꿔도 그렇습니다. 따라서 유의성만으로는 개입의 효과라고 말할 수 없고, 노이즈 바닥보다 커야 합니다. 이 기준으로 살아남는 것은 60k 하나뿐입니다.

60k의 "다양성"은 성능이 아니라 열화입니다

60k는 모든 λ에서 롱테일 노출이 가장 높습니다 (λ=0에서 0.1075 vs 0.0496, 2.2배). 그냥 보면 "60k가 더 다양하다"로 읽힙니다. 그렇게 읽으면 안 됩니다.

  • 무효 SID 비율이 3.606%로 clip_L4(1.424%)의 2.5배
  • 도달률은 91.6%로 가장 높지만(clip_L4 84.2%), 정확도는 모든 λ에서 가장 낮음
  • 60k@λ=0은 clip_L4@λ=0.5에 지배당합니다 — NDCG 0.0342 < 0.0347이면서 롱테일 노출 0.1075 < 0.1706. 두 축 모두 집니다.

과학습이 생성 분포를 평평하게 만들어 "아무거나 더 많이 뱉는" 상태이고, 그 부산물이 롱테일 노출 증가입니다. 좋은 모델에 다이얼을 다는 쪽이 두 축 모두에서 이깁니다.

06

이 숫자를 믿어도 되는 근거

막혀 있던 지점은 두 가지였고, 둘 다 조용히 틀린 답을 주는 종류였습니다.

함정 ① 기존 예측 파일은 정답이 새고 있었습니다

src.inference(predict_step)는 전체 시퀀스를 넣고 "그 다음"을 생성하는 실서비스용 경로입니다. 정답을 가리지 않습니다.

학습 로그 (정답 가림)predict_step 산출물
Recall@50.04440.0576  (+30%)
Recall@100.06600.0961  (+46%)

기존 tiger_runs/*/infer/merged_predictions.pkl 3개는 전부 이 문제가 있습니다. 쓰면 안 됩니다.

함정 ② train=False로 평가하면 랜덤 가중치가 실립니다

src/train.py의 test 블록은 ckpt_path를 설정에서 읽지 않고 ModelCheckpoint 콜백의 best_model_path만 봅니다. 학습을 건너뛰면 그 값이 비어 있어 초기화 직후의 랜덤 가중치로 평가합니다. 경고 한 줄만 나오고 조용히 진행됩니다.

함정 ③ 접두사 제약 디코딩은 GRID 버그로 실행 자체가 안 됩니다

should_check_prefix=True를 켜면 첫 배치에서 즉시 죽습니다. _beam_search_one_step에서 첫 계층일 때는 이미 candidate_logits[:, ~mask]로 열을 마스킹해 놓고, if/else 밖의 공용 줄에서 같은 1-D 마스크로 행을 다시 인덱싱합니다. 한 줄을 else 안으로 들여쓰면 고쳐집니다. 배치 크기가 코드북 크기(256)와 다르면 항상 죽으므로 이 경로는 한 번도 실행된 적이 없다고 봐야 합니다. 팀 공유 저장소라 패치하지 않고 보고만 했습니다.

해결 — eval_step을 가로채는 콜백

올바른 경로는 test_step → eval_step입니다. test 데이터로더가 NextKTokenMasking으로 마지막 K 토큰(=정답 SID)을 마스킹해 넣어 주기 때문입니다. 서버 GRID는 팀원과 공유하므로 기존 파일은 한 줄도 고치지 않고 신규 파일 3개만 추가했습니다. 테스트 시작 시점에 두 지점만 런타임에 감싸고, 끝나면 원상복구합니다.

검증 세 겹

  1. 덤프 경로가 학습 로그와 같은 경로임을 소수점까지 확인. TOPK=10으로 덤프하면 metrics.csv의 recall@5 = 0.04444842040538788과 비트 단위로 일치합니다.
  2. 우리 하네스가 GRID 지표를 독립적으로 재현. SID를 item_id로 되돌려 자체 계산한 recall@10이 0.0660 / 0.0692로 GRID 내부 값과 일치합니다.
  3. 정답 SID 대조 22,363 / 22,363 일치. 덤프에 함께 들어 있는 "모델이 채점에 쓴 정답"을 split의 loo_test와 전건 대조했습니다.
07

트랙 C 프로토콜 (제안)

기존 두 트랙과 나란히 놓을 세 번째 트랙의 정의입니다. 팀 합의가 필요합니다.

항목결정근거
분할 Split A (LOO) 재사용 다양성은 노출 분포 기반이라 시간 분할이 원리적으로 불필요합니다. Split B 블로커를 우회하고 베이스라인과 즉시 비교됩니다. B가 고쳐지면 같은 지표 코드를 그대로 얹으면 됩니다.
롱테일 경계 tail_frac=0.5 유지 이 데이터의 실제 80/20 지점이 상위 45.5%입니다(상위 50%가 상호작용의 82.4%를 차지). 0.5가 데이터의 파레토 지점과 거의 일치합니다. 경계를 0.5~0.9로 바꿔도 실제 모델끼리의 순위는 불변입니다.
파레토 축 NDCG@10 × APLT@10 컷오프는 정확도 파트(Recall@5/@10)와 맞춰 @10으로 고정합니다. 다양성 축의 정식 명칭은 APLT(Average Percentage of Long Tail items)이고 내부 키 tail_exposure와 같은 값입니다. Coverage는 변별력이 약해(ItemKNN 0.96, EASE_R 0.84, Random 1.0) 보조 지표로만 쓰십시오. 콜드 축만 @50 — 콜드 아이템은 top-10에 거의 안 잡힙니다.
다이얼 TIGER = 참조선
본 곡선은 MaskGR		 팀브리핑 원래 설계를 유지합니다. 단 TIGER도 점 하나로 두지 마십시오 — 비용이 0이고, MaskGR 곡선을 평가할 기준선이 됩니다.
지표를 중복해서 보고하지 마십시오 aplt@k와 tail_exposure@k는 사실상 같은 값입니다. 전자는 유저별 비율의 평균, 후자는 전체 슬롯 비율이라 목록 길이가 같으면 수학적으로 동일하고, 실측에서도 소수점 4자리까지 같습니다(TIGER @10에서 둘 다 0.0497). 둘을 독립 지표처럼 나란히 보고하면 안 됩니다. 하나만 고르십시오 — 권장은 APLT입니다.

실험 간 반드시 고정할 것

  • top_k_for_generation — 빔 폭이라 넓히면 상위 10개도 달라집니다(10 → 50에서 Recall@10 0.0660 → 0.0692, +4.9%). 고정하지 않으면 SID 효과와 구분이 안 됩니다.
  • should_check_prefix=False — 지금까지 보고한 지표는 전부 이 기준입니다. 바꾸면 전 지표 재측정이 필요합니다. 무효 SID 비율은 top-10에서 0.035%, top-50에서 0.281%, top-200에서 1.424%로 뒤로 갈수록 늘어납니다.

재현

서버에서 덤프를 뽑는 데 약 1분, 로컬 계산은 즉시입니다.

# 서버 — 정답이 가려진 추천 결과 덤프
sbatch --export=ALL,TAG=clip_L4,TOPK=10  tiger_eval_dump.sh   # 먼저 metrics.csv 와 대조
sbatch --export=ALL,TAG=clip_L4,TOPK=200 tiger_eval_dump.sh   # 본 실행

# 로컬 — 지표 계산
python code/baselines_a.py
python code/tiger_to_eval.py --pred .../eval_dump_k50/test_predictions_rank0.pkl --label clip_L4
python code/pareto_dial.py   --pred .../eval_dump_k200/test_predictions_rank0.pkl \
                             --label clip_L4_k200 --k 20 --lams 0,0.2,0.5,1,2,3,5,8,12
python code/significance.py  --pred .../eval_dump_k50/test_predictions_rank0.pkl
python code/tail_sensitivity.py
python code/compare_table.py results/*.json --k 10

다음 단계

  • GRID 버그 패치 여부 팀 결정 — 한 줄 들여쓰기면 고쳐지지만 공유 저장소라 손대지 않았습니다. 고치면 zero-shot 벽이 낮아지는지 확인할 수 있고, 그 결과에 따라 03절 결론이 바뀝니다.
  • zero-shot 벽을 넘는 방법 — 트랙 C가 찾아낸 가장 큰 미해결 문제. 후보에 유효 SID를 강제로 섞는 방식, 또는 ④번 칸(MaskGR)의 생성 다이얼.
  • 노출 인지 다이얼의 순서 의존성 — 순서를 섞었을 때 지표가 얼마나 흔들리는지 재 두면 방어가 쉬워집니다.
  • ④번 칸(MaskGR) 곡선이 나오면 같은 하네스에 그대로 얹기 — 코드 변경 불필요
  • Split B가 고쳐지면 같은 지표를 그 위에 얹기
