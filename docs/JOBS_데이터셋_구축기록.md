## 3. 결정 기록 — 바꾼 것과 이유

### 3-1. 🔴 한글 → 영문 프로필 (가장 큰 변경)

`google/flan-t5-xl` 토크나이저가 **한글 어절을 통째로 `<unk>` 로 만든다.** 실측:

```
"공인회계사로 6년간 중소·중견기업 회계감사와 세무조정을 담당했습니다."
→ ['▁','<unk>','▁6','<unk>','▁','<unk>','▁','<unk>','▁','<unk>','▁','<unk>','.','</s>']
   14토큰 중 6개가 <unk>. 남는 건 숫자와 마침표뿐.

영문 동일 문장 → 16토큰, unk 0개
```

한글로는 임베딩이 의미를 담지 못하므로 SID 도 무의미해진다. **영문으로 전환.**

- 파이프라인을 하나도 바꾸지 않고 Beauty 와 **같은 인코더**를 쓴다
  → "조건을 바꿔서 좋아진 것 아니냐"는 반론이 차단된다
- 링크드인 시나리오와도 맞는다
- 직업명 492종은 영문 대응 작성 (`data_gen/job_titles_en.tsv`)
- 스킬 77종은 **O*NET 원명 복원** — 고용24 지식 33개가 O*NET Knowledge 33개와
  개수·내용이 대응한다. 번역이 아니라 복원에 가깝다 (`data_gen/skill_names_en.tsv`)

최종 임베딩 검증: **unk 0.0000% · 128토큰 초과 0/12,000**

### 3-2. `skill_vector` 간선을 "다른 직업만" 으로 제한

처음 만든 그래프를 최악 가정(텍스트=직업명만)으로 재보니 `skill_vector` 가
**Jaccard 0.2649** 로 가장 위험했다. 스킬 벡터가 직업 기준 벡터에서 파생되므로
최근접 이웃이 결국 같은 직업 사람이 되어, `same_occupation` 을 다르게 부른 것이었다.

→ **같은 직업을 제외**하고 이웃을 뽑도록 변경. 0.2649 → 0.0000.
임시방편이 아니라 시나리오에 더 맞는다: *"직업은 다른데 역량이 겹치는 사람"*.

### 3-3. `same_occupation` 강등 (사전 예고대로)

사전등록에서 4순위 **강등 후보**로 미리 지목했던 관계. 실제로 떨어졌다.

⚠️ **Jaccard 만 봤으면 통과시킬 뻔했다** (0.0203). 같은 KECO 그룹에서 *무작위* 4명을
뽑으니 텍스트가 고른 *가장 비슷한* 10명과 안 겹칠 뿐이었다.
자를 하나 더 대서 잡았다 — **간선이 잇는 두 사람의 텍스트 코사인**:

| relation | 텍스트 코사인 | 무작위 대비 |
|---|---|---|
| `career_path` | 0.0096 | +0.0093 |
| `skill_vector` | 0.1534 | +0.1531 |
| `related_occupation` | 0.1743 | +0.1740 |
| **`same_occupation`** | **0.2855** | **+0.2852** |
| *(무작위 쌍)* | 0.0003 | — |

다른 관계의 1.6~30배. **정확도 결과를 보기 전에** 판정했다.

### 3-4. 시뮬레이터 — 겪은 실패 두 개

**① 담당자를 한 시점에만 활동시켰더니 Temporal 트랙이 성립하지 않았다.**
담당자의 컨택이 전부 한 윈도우에 몰려 **학습 이력이 있는 테스트 유저가 0명**이 됐다.
→ 담당자에게 활동 기간(중앙 약 300일)을 주고 컨택을 그 기간에 흩었다.

**② 컨택 시각은 흩어놓고 후보 자격은 시작 시점으로 판정했다.**
늦게 등록한 프로필이 영영 후보에 못 들어가 **컨택 0회가 50%** 로 튀었다.
→ 자격을 **각 컨택 시각** 기준으로 바꿨다.

### 3-5. 분포 보정 — 무엇을 맞추고 무엇을 안 맞췄나

인기 되먹임 γ 를 훑어 **상위 50% 집중도**를 Beauty(82.4%) 근처에 맞췄다 (γ=0.45 → 82.8%).
**이것은 분포 보정이지 결과 보정이 아니다** (사전등록 §3-1).

반면 온도를 아무리 올려도 집중도가 87% 아래로 안 내려가던 국면에서는
**억지로 맞추지 않고 멈췄다.** Beauty 는 목표가 아니라 참고선이고, 맞을 때까지
돌리는 것 자체가 과적합이기 때문이다.

## 4. 게이트 결과

### G0 — 그래프 ↔ 텍스트 비중첩 ✅ 통과

판정선은 Beauty 를 **같은 구현으로 다시 재서** 잡았다 (`docs/G0_비중첩.md`).

```
< 0.087        통과 — 채택된 그래프들이 있는 구간
0.087 ~ 0.114  주의
>= 0.114       실패 — 강등된 속성 그래프와 같은 처지
```

| relation | Jaccard | 판정 |
|---|---|---|
| `related_occupation` | 0.0051 | ✅ |
| `skill_vector` | 0.0044 | ✅ |
| `career_path` | 0.0002 | ✅ |
| **합집합 (최종 그래프)** | **0.0052** | ✅ |

**겹침이 너무 낮은 게 오히려 의심스러워** 텍스트가 의미를 담았는지 따로 확인했다:

```
텍스트 이웃의 29.4% 가 같은 직업   (무작위 대비 54.8배)
           38.4% 가 같은 중분류   (무작위 대비 29.2배)
지역·학력은 1.6~1.8배 — 부차 정보로만 반영
```

텍스트는 정상이다. 겹침이 낮은 이유는 **텍스트가 같은 직업을 모으고 우리 그래프는
일부러 다른 직업을 잇기** 때문 — 의도한 상보성이다.

## 6. 재현 경로

```bash
# 1. 공공 데이터 수집 (이어받기 지원)
python data_gen/fetch_work24.py

python data_gen/build_profiles.py
python data_gen/write_profile_text.py

# 3. 임베딩 (서버 GPU, 약 4분)
sbatch embed_jobs.sh

# 4. 그래프 → G0 판정
python data_gen/build_job_graph.py
python data_gen/rewire_null.py            # G1 대조군

# 5. 상호작용 → Split A/B
python data_gen/simulate_interactions.py --temp 0.15 --gamma 0.20 --cand-pool 12000
python data_gen/build_splits.py
python data_gen/gate_learnability.py      # ← G-L. 통과 전에는 GPU 제출 금지

# 6. TFRecord → SID → 학습 (서버)
python to_grid_v2.py jobs/Jobs_split_A.pkl grid_data/jobs_A
sbatch --export=ALL,TAG=jobs_gsid_b10,EMB=...,LEVELS=4 sid_jobs.sh
sbatch --export=ALL,TAG=jobs_gsid_b10_s42,SID=...,DATA=...,SEED=42 tiger_beauty.sh
```

난수는 전부 `--seed` 로 고정. 같은 시드면 같은 데이터가 나온다.

## 7. 알려진 한계 (숨기지 않는다)

1. **순환이 완전히 사라지지 않았다.** 그래프(`skill_vector`)와 담당자 점수 함수가
   같은 스킬 벡터에서 나온다. 담당자는 요구 차원 20개만 관측 잡음을 통해 보고
   그래프는 전체 77차원을 쓰도록 분리했지만, 결합은 남는다.
   **남은 결합의 크기는 G1 이 잰다.**
2. **채용공고 실데이터가 없다** (개인회원 차단). 직무 어휘는 직업정보의
   구조화된 지식·능력 벡터로 대체했다.
3. **전공 계열이 직업과 어색한 조합이 섞인다.** 고용24 실제 분포를 그대로 뽑은
   결과이며(저학력 직업군은 전공 분포가 흩어져 있다) 조작하지 않았다.
4. **`career_path` 간선이 5,530개로 희소하다.** 학과명을 `technKnow` 서술문에서
   추출하는데 492개 직업 중 117개에서만 성공했기 때문이다.
5. **집중도가 Beauty 보다 약간 높다** (82.8% vs 82.4% — 근접하나, 조정 과정에서
   87% 아래로 안 내려가던 국면이 있었다. §3-5 참고).
