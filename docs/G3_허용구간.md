# G3 허용 구간 — v4 데이터 생성 전에 고정

작성 2026-09-15. 사전등록 §5 G3 와 §10 산출물에 해당한다. **이 구간은 v4 상호작용을 만들기 전에 정했고, 이후 바꾸지 않는다.** 바꿔야 하면 사전등록 §9 절차로 기록한다.

같은 값이 `data_gen/spec/g3_tolerance.json` 에 있고 `data_gen/v4/gate_g3_stats.py` 가 읽는다.

## 1. 대조 대상

| 원래 계획 (2026-08-30) | 실제 (2026-09-15) | 이유 |
|---|---|---|
| 직종·지역 분포 ↔ 고용24 채용정보 | **대조하지 않는다.** 직종·지역은 프로필 생성 시 고용24 직업정보 실분포(학력·전공)와 명시한 가정(지역 편중)에서 뽑는다 | 채용정보 API 가 개인회원 차단 |
| 인기도 Gini ↔ Beauty | **캐글 CareerBuilder 2012 실측을 목표**, Beauty 는 참고선 | 캐글은 실제 지원 로그다. Beauty 는 전자상거래라 쏠림 성질이 다르다 |
| 시퀀스 길이 분포 ↔ Beauty | 캐글 사용자당 지원 수 분포를 목표 | 같은 이유 |
| 롱테일 경계 | 캐글 상위 50% 점유율·3건 이하 비율·0건 비율 | 같은 이유 |

캐글 값은 `python data_gen/v4/kaggle_stats.py` 가 `data_gen/spec/kaggle_target_dist.json` 과 `docs/G3_목표분포_캐글.md` 에 쓴다. 원본은 저장소 밖에 두고 집계값만 남긴다.

## 2. 허용 구간

오차 종류: rel = |생성 − 목표| / |목표|, abs = |생성 − 목표| (비율 지표). PASS ≤ WARN 한계 < WARN ≤ FAIL 한계 < FAIL.

| 항목 | 키 | 종류 | WARN 한계 | FAIL 한계 | 왜 이 폭인가 |
|---|---|---|---|---|---|
| 사용자당 건수 중앙 | apps_per_user/p50 | rel | 0.25 | 0.50 | 담당자당 컨택 수는 로그정규 파라미터로 직접 조정 가능하다. 넉넉히 잡을 이유가 없다 |
| 사용자당 건수 평균 | apps_per_user/mean | rel | 0.25 | 0.50 | 위와 같다 |
| 사용자당 건수 p90 | apps_per_user/p90 | rel | 0.35 | 0.70 | 꼬리는 분산이 커서 중앙보다 느슨하게 |
| 3건 이상 사용자 비율 | apps_per_user/share_ge3 | abs | 0.10 | 0.20 | LOO 채점 가능 유저 비율. 실험 성립 조건이라 FAIL 을 둔다 |
| 아이템 Gini (1건 이상) | apps_per_job_applied_only/gini | abs | 0.05 | 0.10 | 인기 쏠림의 핵심 지표 |
| 상위 50% 아이템 점유율 | apps_per_job_applied_only/top50_share | abs | 0.05 | 0.10 | v3 에서 92.6% 로 튀었던 지표. 가장 엄격하게 본다 |
| 3건 이하 아이템 비율 | apps_per_job_applied_only/share_le3 | abs | 0.10 | 0.20 | few-shot 버킷 크기 |
| 0건 아이템 비율 | share_jobs_with_zero_apps | abs | 0.10 | 0.20 | zero-shot 버킷 크기. 캐글은 전체 공고 대비, 우리는 전체 프로필 대비 |
| 활동 기간 중앙(일) | user_active_span_days/p50 | rel | 0.50 | 1.00 | 캐글 윈도우는 약 3개월, 우리는 2년 시뮬레이션이라 절대값 정합은 무리. 자릿수만 본다 |
| 경력 연수 중앙 | total_years_experience/p50 | rel | 0.35 | 0.70 | 프로필 생성기(`build_profiles.py`)의 로그정규 가정 검증. v4 에서 프로필은 다시 만들지 않으므로 참고용 |

게이트 통과 = FAIL 0개. WARN 은 통과하되 `docs/G3_통계정합성.md` 에 남긴다.

## 4. 캘리브레이션에서 만지는 것과 안 만지는 것

| 파라미터 | v3 값 | v4 | 순환 영향 |
|---|---|---|---|
| TEMP | 0.15 | 격자 {0.10, 0.15, 0.25} | 없음 |
| GAMMA | 0.20 | 격자 {0.10, 0.20, 0.35} | 없음 |
| K_MU, K_SIGMA (담당자당 컨택 수) | 1.55, 0.75 | 격자 {1.55} × {0.75, 1.0} | 없음 |
| CAND_POOL | 12000 | 고정 | 없음 |
| OBS_NOISE | 14.0 | **고정** | 있음 |
| SIGMA_R | 10.0 | **고정** | 있음 (JOBS_학습실패_원인분석 §6) |
| TOP_M | 20 | **고정** | 있음 |

선택 규칙(실행 전 고정): G-L 통과(ContentKNN/Pop ≥ 1.5, ItemKNN/Pop ≥ 1.5) 후보 중 G3 점수(항목별 오차/WARN 한계의 합)가 최소인 것. 동점이면 v3 값에 가까운 것. `data_gen/v4/calibrate_simulator.py`.

v3 에서 확인한 제약을 잊지 않는다. 협업 신호(담당자 간 합의)와 노출 쏠림은 같은 양이라, 쏠림을 캐글 수준으로 내리다 G-L 이 깨지면 **G-L 이 우선**이다. 그 경우 G3 는 WARN·FAIL 을 그대로 기록하고 도메인 성질로 설명한다.
