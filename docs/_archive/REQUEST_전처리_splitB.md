## 2. 왜 바꿔야 하는가 — 실측 근거

우리가 Split B로 재려는 것은 **"콜드 아이템이 normal 아이템보다 얼마나 못 잡히는가"** 입니다.
그러려면 비교 기준선이 되는 **normal 아이템이 test 에 충분히 있어야** 합니다.

현재 방식으로 만들면 이렇습니다 (`stratify_cold()` 의 실제 임계값 적용):

| 라벨 | train | val | test | normal | rare | very_rare | unseen | **test에 등장한 normal** |
|---|---|---|---|---|---|---|---|---|
| W3 | 75 | 502 | 4,738 | 0 | 0 | 69 | 12,032 | **0** |
| W4 | 577 | 4,738 | 20,872 | 6 | 14 | 364 | 11,717 | **5** |
| W5 | 5,315 | 20,872 | 172,315 | 100 | 127 | 1,453 | 10,421 | **75** |

- W3는 train 이 **75건**이라 학습 자체가 불가능합니다.
- W5조차 아이템 12,101개 중 **10,421개(86%)가 `unseen`** 이고 normal 은 100개뿐입니다.
- **test 에 실제로 등장하는 normal 아이템이 0~75개** → 콜드와 비교할 대조군이 없습니다.

원인은 구현 오류가 아니라 **데이터의 시간 쏠림**입니다. 리뷰가 2013년에 몰려 있어서
(2002년 4건 vs 2013년 85,251건) 달력을 균등하게 자르면 초기 윈도우가 텅 빕니다.

윈도우별 리뷰 수: **75 / 502 / 4,738 / 20,872 / 172,315**

> 참고로 Split A(LOO)의 버킷 분포는 head 7,838 / mid 8,328 / low 4,559 / few-shot 1,500 /
> zero-shot 138 로 대조가 충분합니다. Split B만 이 상태입니다.

## 3. 제안 — 리뷰 건수 기준 균등 5등분 (P3)

같은 코드로 등분 기준만 바꾸면 이렇게 됩니다:

| 라벨 | train | val | test | normal | rare | very_rare | unseen | **test에 등장한 normal** |
|---|---|---|---|---|---|---|---|---|
| W3 | 39,700 | 39,700 | 39,701 | 1,653 | 1,372 | 4,687 | 4,389 | **1,356** |
| W4 | 79,400 | 39,701 | 39,700 | 3,651 | 2,395 | 4,138 | 1,917 | **2,956** |
| W5 | 119,101 | 39,700 | 39,701 | 5,721 | 2,989 | 2,469 | 922 | **4,091** |

윈도우 경계: **2012-08-16 / 2013-04-05 / 2013-09-28 / 2014-03-07**

이 방식의 장점:

1. **세 윈도우가 전부 살아납니다.** 원래 설계 의도(W3/W4/W5 추이 비교)가 복원됩니다.
2. **콜드 심각도가 자연스러운 단계를 이룹니다** — unseen 이 4,389 → 1,917 → 922 로 줄고
   normal 이 1,653 → 3,651 → 5,721 로 늡니다. "학습 데이터가 쌓일수록 콜드 문제가
   완화되는가"를 보여주는 **그 자체로 좋은 실험 축**이 됩니다.
3. train 이 39,700~119,101건이라 **학습이 가능합니다.**
4. 콜드와 normal 양쪽 다 충분해서 **버킷별 정확도 곡선을 그릴 수 있습니다.**

### 검토했으나 택하지 않은 대안

| 대안 | 결과 | 기각 사유 |
|---|---|---|
| 리뷰 건수 80/10/10 단일 컷 | train 158,801 / unseen 310 | 콜드 아이템이 너무 적어 콜드 실험이 성립 안 함 |
| 달력 균등 10등분 후 뒤쪽만 사용 | train 26,187 / normal 771 | normal 이 여전히 부족 |

## 4. 코드 변경안

`preprocess.py` 의 `split_chronological_windows()` 하나만 바꾸면 됩니다.

```python
def split_chronological_windows(reviews, n_windows=5, by='count'):
    """
    by='time'  : 전체 기간을 달력 기준 균등 n등분 (Can GR Reach Cold Items? 논문 원안)
    by='count' : 리뷰 건수 기준 균등 n등분 (기본값)

    ★ by='time' 은 이 데이터에서 초기 윈도우가 사실상 비어(75/502건) 실험 불가라
      기본값을 'count' 로 둔다. 논문 재현이 필요하면 by='time' 으로 호출할 것.
    """
    # 동점 시각의 2차 정렬 키를 고정해 재현성 확보
    rows = sorted(reviews, key=lambda r: (r['unixReviewTime'], r['asin'], r['reviewerID']))

    if by == 'time':
        times = [r['unixReviewTime'] for r in rows]
        t_min, t_max = min(times), max(times)
        span = t_max - t_min
        bounds_ts = [t_min + span * i / n_windows for i in range(n_windows + 1)]
    else:
        # 건수 분위수로 자르되, 경계를 '타임스탬프 단위'로 스냅한다.
        # 이 데이터는 타임스탬프가 일 단위(고유 2,927개, 하루 평균 15건, 최대 634건)라
        # 인덱스로 그냥 자르면 같은 날이 train 과 test 양쪽에 걸쳐 누수가 된다.
        n = len(rows)
        bounds_ts = [rows[0]['unixReviewTime']]
        for i in range(1, n_windows):
            t = rows[int(n * i / n_windows)]['unixReviewTime']
            bounds_ts.append(t)
        bounds_ts.append(rows[-1]['unixReviewTime'])

    windows = []
    for i in range(n_windows):
        lo, hi = bounds_ts[i], bounds_ts[i + 1]
        if i == n_windows - 1:
            w = [r for r in rows if lo <= r['unixReviewTime'] <= hi]
        else:
            w = [r for r in rows if lo <= r['unixReviewTime'] < hi]
        windows.append(w)
    return windows  # [W1, W2, ..., Wn]
```

경계 스냅으로 이동하는 리뷰는 경계당 **85~634건(전체의 0.04~0.32%)** 이라 윈도우 균형에
실질적 영향은 없습니다. 대신 **같은 날 이벤트가 분할선을 넘나드는 누수를 막습니다.**
