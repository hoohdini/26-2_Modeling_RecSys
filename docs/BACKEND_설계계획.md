# 백엔드 설계 계획 — ORBIT 행사 서비스 (2026-09-20)

백엔드를 같이 만들 사람에게 주는 문서다. 무엇을 만들고, 어디에 두고, 어떤 순서로 만들지 적었다. 처음 나오는 말은 마지막 절의 용어 풀이에 있다. 이 계획은 9/26 회의에서 확정하고, 확정 전까지는 제안이다.

## 1. 한눈에

1. 계산(임베딩, 주소 발급, 테이블 배정, 추천)은 컨테이너 하나에 넣는다. 학교 GPU 서버는 쓰지 않는다. 경량 모델이라 CPU로 충분하다.
2. 상태(참가자, 명함, 교환 기록, 배정 결과)는 Firebase에 둔다. 계산 서비스는 상태를 갖지 않는다.
3. 점수는 벡터로 계산하고, 주소(SID)는 화면에 보이는 이름표와 테이블 묶음, 미션 조건에만 쓴다.
4. 사람마다 주소를 두 개 만든다. Offer(지금 하는 일)와 Seek(오늘 찾는 사람)이다.
5. 행사 중 계산은 정해진 두 시점(체크인 마감, 테이블토크 종료)에만 한다. 결과는 버전 번호를 붙여 저장하고 운영자가 확인한 뒤 공개한다. 자동 발송은 없다.

## 2. 무엇을 만드나

| 순위 | 기능 | 백엔드가 하는 일 |
|---|---|---|
| P0 | 등록과 주소 발급 | 등록 폼을 받아 Offer·Seek 벡터와 주소를 만들고 저장한다. 워크인도 같은 경로다 |
| P0 | 모바일 명함 | 저장된 프로필과 주소를 명함 화면에 준다. 공개 범위를 지킨다 |
| P0 | 테이블토크 배정 | 체크인 명단으로 테이블을 짜고 운영자 확인 뒤 참가자에게 테이블 번호와 테이블 공통 관심사를 보여준다 |
| P0 | 피드백과 명함 교환 기록 | 테이블토크 뒤 더 얘기하고 싶은 사람 선택, QR 명함 교환을 간선으로 저장한다 |
| P0 | 커피챗 재배정 | 간선으로 주소를 다시 발급하고 상호 점수로 테이블을 다시 짠다. 같은 조원은 다시 묶지 않는다 |
| P0 | 개인 추천 | 아직 안 만난 사람 중 12명(정확 10, 탐색 2)을 이유와 함께 준다 |
| P1 | 미션 카드 판정 | QR 상호 스캔 기록으로 미션 조건을 자동 판정한다 |
| P1 | 운영 콘솔 | 응답률, 배정 버전, 미배정자, 간선 없는 사람을 보여주고 배정 공개 버튼을 둔다 |
| P2 | 행사 후 리포트 | 누가 몇 명을 만났는지 집계한다 |

## 3. 구조

```
참가자 폰 (설치 없는 웹앱)
   │  읽기·쓰기 (자기 것만)
   ▼
Firebase 실시간 DB  ←→  계산 서비스 (컨테이너 1대)
   상태 전부              임베딩 모델 + 코드북 + 배정 엔진
                         상태 없음, 행사 전날 만든 코드북만 메모리에 들고 있음
```

계산 서비스는 세 가지 일만 한다.

| 진입점 | 언제 | 하는 일 | 걸리는 시간 |
|---|---|---|---|
| 발급 | 등록 요청마다 | 문장 두 개를 임베딩하고 코드북에 배정해 주소를 돌려준다 | 1초 미만 |
| 배정 | 운영자가 누를 때 | 체크인 명단으로 테이블을 짜서 버전 번호를 붙여 저장한다 | 1분 안 (지금 코드 38초, 개선 후 수초) |
| 추천 | 배정 뒤 한 번, 명함 교환이 쌓이면 한 번 더 | 사람마다 12칸 목록을 만들어 저장한다 | 수초 |

## 4. 컨테이너

| 항목 | 내용 |
|---|---|
| 들어가는 것 | Python, 임베딩 모델 multilingual-e5-small(384차원), 코드북 학습·배정 코드, 배정 엔진, Firebase 접근 키 |
| 메모리 | 1~2GB. ONNX 정수화 버전을 쓰면 512MB에도 들어간다 |
| 모델 파일 | 이미지에 미리 넣는다. 부팅 때 내려받게 두면 첫 요청이 수십 초 걸린다 |
| 무거운 계산 | 배정과 추천은 백그라운드 작업으로 돌린다. 요청 안에서 38초를 돌리면 타임아웃과 중복 실행이 생긴다 |
| 호스팅 | 1순위 Oracle Cloud Always Free ARM 가상머신(4코어 24GB, 항상 켜짐). 2순위 Hugging Face Spaces 도커(2코어 16GB, 48시간 비활성 시 잠듦). 둘 다 무료 |
| 예비 | 같은 이미지를 운영자 노트북에 띄우고 Cloudflare Tunnel(무료)로 같은 주소에 붙인다. 클라우드가 죽으면 프론트 설정 하나만 바꾼다 |
| 개인정보 | 계산 서비스는 익명 번호와 문장만 받는다. 이름·연락처는 Firebase에만 있다 |

## 5. DB 설계 (Firebase 실시간 DB)

| 노드 | 내용 | 누가 쓰나 |
|---|---|---|
| participants/{uid} | 이름, 소속, 구분, 기수, 공개 범위, 동의 시각 | 본인만 |
| profiles/{uid} | Offer 문장, Seek 문장, 태그 | 본인만 |
| sids/{uid} | Offer 주소, Seek 주소, G-SID 주소, 코드북 버전, 발급 시각 | 계산 서비스만 |
| checkins/{uid} | 체크인 시각, 지연 도착 여부 | 운영자 |
| edges/{uid}/{peer} | 종류(피드백 선택, 명함 교환, 같은 테이블), 시각 | 본인과 계산 서비스 |
| tables/{version}/{table} | 구성원 목록, 공통 관심사 라벨, 공개 여부 | 계산 서비스가 쓰고 운영자가 공개 |
| recs/{version}/{uid} | 추천 12칸, 각 칸의 이유 | 계산 서비스만 |
| labels/{code} | 주소 앞자리에 붙이는 사람이 읽는 이름 | 행사 전날 한 번 |
| ops/ | 현재 공개된 배정 버전, 응답률, 계산 서비스 생존 신호 | 계산 서비스와 운영자 |

규칙 세 가지. 참가자는 자기 uid 아래만 쓴다. sids, tables, recs는 참가자에게 읽기 전용이다. 개인정보는 행사 뒤 30일에 지운다.

## 6. 주소 발급 파이프라인

| 단계 | 하는 일 | 주의 |
|---|---|---|
| 1 문장 만들기 | 소속·구분·태그를 정해진 틀 문장으로 감싸고 자유서술 두 줄을 붙인다 | Offer와 Seek는 같은 틀을 쓴다. 길이는 각 120자로 제한한다 |
| 2 임베딩 | 두 문장을 각각 벡터로 만든다 | 둘 다 같은 접두사(passage)로 넣는다. Seek만 query로 넣으면 캐글 시험에서 코드북이 문체로 갈렸다 |
| 3 평균 빼기 | Offer 벡터 전체 평균을 두 벡터에서 뺀다 | 이걸 빼지 않으면 Offer와 Seek가 한 코드북에서 다른 칸으로 몰린다 |
| 4 코드북 배정 | 사전 등록자의 Offer로 행사 전날 코드북(K=8, 3단계)을 학습해 고정하고, 두 벡터를 여기에 배정한다 | 행사 당일에는 재학습하지 않는다. 워크인은 배정만 한다 |
| 5 충돌 구분자 | 같은 주소가 나오면 4번째 자리로 구분한다 | 문장이 같으면 주소가 같다. 등록 폼의 자유서술이 이걸 막는다 |
| 6 이름표 | 앞자리별로 사람이 읽는 라벨을 붙인다 | 전날 만들어 labels에 저장, 운영진이 검수 |
| 7 재발급 | 테이블토크 뒤 간선으로 Offer 벡터에 이웃 정보를 더해 G-SID를 만든다 | 세기 β₀는 설정값. 한 동네가 35%를 넘으면 반으로 줄인다. 간선 없는 사람은 원래 주소 유지 |

Seek가 비어 있으면 Offer로 대체하고, 명함 교환이 쌓이면 교환 상대의 Offer 평균을 더해 대체한다.

## 7. 배정 엔진

| 항목 | 내용 |
|---|---|
| 입력 | 체크인 명단, 쌍 점수 표, 테이블 크기 범위(5~6), 호스트(알럼나이) 명단, 금지 쌍(이미 같은 테이블이었던 쌍) |
| 점수 | 테이블토크는 Offer끼리 유사도. 커피챗은 min(내 Seek와 상대 Offer, 상대 Seek와 내 Offer). 약한 쪽이 결정하므로 한쪽만 좋은 쌍이 올라오지 않는다 |
| 목표 | 개인 만족(테이블 동료 평균 점수)의 평균과 하위 10% 평균을 같이 올린다. 평균만 올리면 인기 있는 사람에게 몰린다 |
| 제약 | 테이블 크기, 호스트를 테이블마다 고르게, 같은 기수 3명 이상 금지, 커피챗은 테이블토크 조원 재회 금지 |
| 방법 | 호스트를 먼저 한 명씩 나눠 앉히고, 나머지를 한 자리씩 채우며 갱신하고, 같은 역할끼리 자리를 바꿔 보는 담금질 |
| 대체 경로 | 피드백 응답률이 50% 미만이면 Offer 유사도와 재회 금지만으로 짠다. 이 분기는 코드에 처음부터 넣는다 |
| 지연 도착 | 즉시 발급하고 가장 작은 테이블에 붙인다 |
| 출력 | tables/{version}. 운영자가 콘솔에서 보고 공개한다 |

## 10. 오류와 오해를 막는 규칙

1. 계산 결과에는 전부 버전 번호가 있다. 화면에도 표시한다. 두 사람이 다른 버전을 보는 일을 막는다.
2. 배정 결과는 운영자가 콘솔에서 공개 버튼을 눌러야 참가자에게 보인다. 자동 발송은 없다.
3. 사람은 uid 하나로만 다룬다. 이름은 표시용이다. 연명부에서 이름 표기가 달랐던 사례가 있다.
4. 테이블 크기와 호스트 수는 인원에 맞춰 코드가 계산한다. 숫자를 하드코딩하지 않는다. 노쇼 한 명으로 깨지는 것을 막는다.
5. 설정값은 한 파일에 모은다. β₀, 코드북 K와 단계 수, 테이블 크기 범위, 응답률 기준, 추천 노출 상한, 동네 크기 상한.
6. 저장 직전에 형식 검사를 한다. 시뮬레이션에서 계산은 끝났는데 저장에서 죽은 일이 있었다.
7. 로그는 한 곳에 모은다. 컨테이너 표준 출력이면 된다.
8. 테스트는 저장소의 시뮬레이션 코드(`event_demo/06_event_loop.py`)를 컨테이너 안에서 그대로 돌리는 것으로 한다. 노쇼·워크인·무응답·장애가 이미 들어 있다.
9. 코드북과 모델 버전을 바꾸면 주소가 전부 바뀐다. 행사 당일에는 바꾸지 않는다.
10. 리허설 없이 당일을 맞지 않는다. 응답률과 등록 병목은 시뮬레이션으로 알 수 없다.

## 12. 용어 풀이

| 용어 | 뜻 |
|---|---|
| 임베딩 | 문장을 숫자 벡터로 바꾼 것. 비슷한 문장은 가까운 벡터가 된다 |
| 코드북 | 벡터 공간을 몇 개 칸으로 나눈 기준점 묶음. 주소는 어느 칸에 떨어졌는지의 번호다 |
| 주소(SID) | 코드북 번호를 3자리로 이어 붙인 것. 앞자리가 같으면 같은 동네다 |
| Offer, Seek | 지금 하는 일 문장과 오늘 찾는 사람 문장. 각각 벡터와 주소가 있다 |
| G-SID | 명함 교환 같은 관계로 이웃의 정보를 더해 다시 만든 주소 |
| 담금질 | 자리를 조금씩 바꿔 보며 점수가 오르면 받아들이고, 가끔 내려가도 받아들여 더 좋은 배치를 찾는 방법 |
| 컨테이너 | 프로그램과 필요한 것을 한 상자로 묶어 어디서나 같게 실행하는 방식 |
| 버전 번호 | 계산할 때마다 하나씩 올리는 번호. 어느 결과가 최신인지 알려 준다 |
