## 1. 30초 스토리

```
문제   생성형 추천(TIGER)은 신규·비인기 아이템을 못 찾는다
가설   아이템 주소(Semantic ID)를 텍스트 대신 그래프로 만들면 나아진다
검증   ① Amazon Beauty   ② 구인구직(자체 구축)  두 도메인
```

**결과 세 줄**

1. **Beauty — 확정.** G-SID 가 텍스트 주소를 이긴다. NDCG@10 +0.0043(노이즈 바닥의 2.7배),
   COLD@50 +47.6%, 3시드·세 트랙 전부 통과. 승자 파라미터 **β₀ = 1.0**
2. **구인구직 — 재현됨.** 정확도 12/12 전부 양수. recall@50 **+11.1%**, ndcg@50 **+10.2%** 유의.
   무작위 그래프 대조(G1) **7/7 통과**. 단 사전등록 주 지표 NDCG@10 은 검정력 부족으로 미확인
3. **zero-shot — 못 뚫었다. 대신 원인을 특정했다.** 디코더가 아니라 **SID 할당 커버리지** 문제.
   같은 정보로 콘텐츠 추천기는 23% 를 잡는데 TIGER 는 0.04% — 생성형 검색이 정보를 버린다

## 4. 인용하면 안 되는 수치 (실제로 틀렸던 것들)

발표 준비 중 옛 대화나 문서에서 이 숫자들을 보면 **쓰지 마세요.**

| 잘못된 수치 | 실제 | 왜 틀렸나 |
|---|---|---|
| 구인구직 COLD@50 "3배 개선" | 시드 부호 반전 — **측정 불가** | v2 2시드 기준. 시드 13 에서 음수 |
| 구인구직 다양성 개선 | **측정 불가** | coverage sd 가 text 0.069 / gsid 0.145 |
| 접두사 제약 롱테일 "+16~19%" | **+8%** | 1시드 기준이었음. 3시드로는 절반 |
| v1·v2 의 모든 지표 | **폐기** | 데이터 버그 / 프로토콜 버그 |

**규칙: 1시드 수치는 인용하지 않습니다.** 이 프로젝트에서 세 번 데였습니다.

## 5. 예상 질문과 답

**Q. 주 지표(NDCG@10)가 실패했는데 결과라고 할 수 있나?**
방향은 +9.2% 로 맞고 3시드 전부 양수입니다. 유의하지 않은 것은 **효과가 없어서가 아니라
n=3 의 검정력 부족**입니다. 계산해서 보였습니다 — `JOBS_결과정리.md` §4-3.
n=5~6 이면 recall@10 은 거의 확실히, ndcg@10 은 경계선에 올라옵니다.

**Q. 짝지은 검정으로 바꾼 건 결과 보고 기준을 바꾼 것 아닌가?**
맞습니다. 순서가 뒤였다는 사실을 문서에 명시했습니다(§4-2). 근거는 효과가 **같은 시드 안의
짝지은 차이**인데 사전등록 바닥은 **서로 다른 시드 간 산포**라 시드 주효과가 장벽으로
잘못 실린다는 것입니다. 두 검정 결과를 나란히 싣습니다.

**Q. 생성 데이터인데 신뢰할 수 있나?**
직무 어휘와 직업 분류는 **발명하지 않았습니다** — 고용24 공공데이터입니다.
합성한 것은 프로필 조합·텍스트·상호작용뿐이고, 상호작용도 LLM 이 아니라 **명시적 수식**입니다.
경계는 `data_gen/README.md` §1 에 표로 있습니다.

**Q. 그래프가 정답지를 보는 것 아닌가 (순환)?**
완전히 배제하지 못했습니다. 담당자는 요구 차원 20개만 관측잡음(σ=14)을 통해 보고
그래프는 전체 77차원을 쓰도록 분리했지만 결합은 남습니다.
**G1 은 차수 아티팩트를 배제할 뿐 순환을 재지 못합니다.** 숨기지 않고 한계로 적었습니다.

**Q. zero-shot 을 못 뚫었으면 실패 아닌가?**
원인을 수치로 특정했습니다 — zero-shot 의 97.6% 가 학습 미방문 코드 경로 위에 있습니다.
계층을 줄이는 것은 답이 아님을 GPU 8분으로 확인해 재학습 13시간을 아꼈습니다.
그리고 2계층 접두사 확장으로 **0 → 0.061 을 열었습니다**(전체 −15% 대가). §8-7.
