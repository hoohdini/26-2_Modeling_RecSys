# CRAB-SID — 코드북 리밸런싱 (Stage 1)

CRAB 논문(arXiv 2604.05113) Section 4.1 재구현. 코드 미공개라 수식 기반으로 직접 구현했다.
이미 만들어진 SID 위에 **후처리(post-hoc)** 로 적용해서, 과인기 토큰을 여러 개로 쪼개
롱테일 아이템의 노출 기회를 늘린다.

- 코드: `crab/crab_sid.py`
- 실행: `python crab/crab_sid.py --embedding-path <emb.pt> --sid-path <sid_tensor.pt> --out-dir <out>`

## 설정 (팀 합의)

| 파라미터 | 값 | 근거 |
| --- | --- | --- |
| `--split-ratio` | 0.10 | 논문 5.1절 구현값. Figure 3에서 5~20% 스윕 |
| `--m-mode` | `fixed` (M=3) | 팀 합의. `adaptive`로 논문 원문(가변, 상한 3) 전환 가능 |
| `--lambda-bal` | 1.0 | 수식 6의 λ. **논문에 값이 없어 우리가 스윕해야 함** |
| `--tail-guard` | 0.5 | G-SID의 head-tail 묶음 보호용 (팀 충돌 조율 규칙) |
| 분할 레벨 | 0,1,2 | 마지막 의미 레벨은 제외 (논문: 이미 세밀해서 쪼개면 성능 하락) |
| 분할 | A (LOO) | B 전환 시 `--interactions-path`만 `B_interactions_long.csv`로 교체 |

## 구현상 알아둘 것

**1. SID 텐서는 전치돼 있다** — GRID 출력이 `(5, 12101)` = `(레벨, 아이템)`.
코드가 자동 감지해서 바로잡고, 저장할 때 원래 방향으로 되돌린다.

**2. L4 = 의미 토큰 4개 + dedup 1개** — 마지막 컬럼(고유값 18~22개, 대부분 0)은
충돌 해소용 일련번호라 분할 대상에서 제외한다(`--drop-dedup-col`, 기본값).

**3. 잔차는 재구성한 값이다** — GRID가 코드북/중심점을 저장해주지 않아서,
임베딩 + SID 배정으로부터 역산한다(k-means 중심점 = 배정된 점들의 평균).
레벨 0에서 재배정 일치율 **0.87~0.94**로 확인됨 — 실용 수준.
더 정확히 하려면 GRID 쪽에서 중심점을 저장하도록 바꿔야 한다.

**4. 임베딩과 SID는 반드시 짝이 맞아야 한다** — 잔차 재구성이 틀어지면 분할이 엉망이 된다.
확인 결과 `graph_augmented_embedding.pt`(태그 없음)가 **a03** 버전이다
(`gsid_a03`과 일치율 0.945로 최고).

## 관찰 / 다음 할 일

**tail_guard가 한 번도 발동하지 않았다 (제외 0개).** 인기도 상위 토큰은 정의상 head가
지배적이라 tail 비율 50%를 넘을 수가 없다. 즉 현재 threshold에서 head-tail 보호 장치는
사실상 비활성이다. `--tail-guard 0.2` 정도로 낮춰서 실제로 걸리는 토큰이 있는지 확인 필요.

**dedup 토큰은 기존 값을 그대로 복원했다.** CRAB 분할로 SID 조합이 바뀌었으니 엄밀히는
재계산이 맞다. `Tokenization/compare_sid_variants.py`로 충돌이 실제로 어떻게 변했는지
먼저 확인하고, 문제가 될 정도면 재계산 로직을 넣는다.

**Gini는 대리 지표다.** CRAB은 노출 형평성(DGU/GU)을 최적화하는 기법이지 Recall을
올리는 기법이 아니다(논문에 콜드스타트 실험 자체가 없음). 최종 판단은 TIGER 학습 후
Recall@k / NDCG@k, 그리고 콜드·롱테일 버킷별 지표로 해야 한다.
**CRAB 적용 후 Recall이 다소 떨어지는 것은 버그가 아니라 설계대로 작동한 증거다.**

**대기 중인 입력**: `_centered` 임베딩, α=0.5 버전. 둘 다 임베딩팀 산출물이 나오면
같은 명령으로 바로 돌릴 수 있다. 요청사항 — **α=0.5는 임베딩과 SID를 한 쌍으로** 주면
좋겠다(임베딩만 오면 GRID를 다시 돌려야 해서 병목).

**λ 스윕 미실시**: `--lambda-bal`은 논문에 값이 없어 현재 1.0 임의값이다.
거리 보존 vs 인기도 균형 트레이드오프라, splitting ratio처럼 스윕이 필요하다.

## Stage 2는 아직 미구현

논문의 CRAB은 2단계다. 여기 구현한 건 **Stage 1(코드북 리밸런싱)** 뿐이다.
Stage 2(수식 9, 계층적 의미 정렬)는 전처리가 아니라 **학습 시 정규화 손실**
(`L = L_Rec + γ·L_T`, 논문 γ=0.2)이라 TIGER/MaskGR 학습 루프에 훅으로 들어가야 한다.
**Stage 1과 2는 반드시 분리해서 ablation할 것** — 통째로 넣으면 어느 쪽 효과인지 알 수 없다.
